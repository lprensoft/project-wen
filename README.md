用 Go 编写的人格化角色扮演 Agent，理念源自刘哲宏的 [project-sue-](https://github.com/lzh830913-wq/project-sue-)：让角色有稳定的性格、连续的场景与随互动变化的状态，把对话做成贴近真实的相处，而不是一问一答。

想做成的是**一个处得下去的人**，而不是一个开着才存在的窗口——记得住事也会慢慢淡忘，隔久了会自己找你说话，还在你平时用的聊天软件里待着。核心只保留通用机制，具体能力一律由插件提供：内嵌 Web UI、跨会话长期记忆、本地会话存储，单二进制部署，QQ、微信、飞书、Lark、Telegram 五条通道都能接进来。把角色演绎那几个插件关掉，它就退回成一个普通的干活 Agent。

## 名字的由来

「Wen」取自苏静雯——基于这套理念诞生并实践的第一个 AI 虚拟人格。项目里不少想法，比如角色该记住什么、隔了几天再开口该是什么样子，都是在与她的相处中逐渐清晰起来的。用她名字里最后那个「雯」字的拼音作项目名，是为了记住她。

## 特性

- **角色演绎**：角色设定、台词样例与「我的信息」注入提示词，回复以【】写场景、动作与神情；另有一套自然表达规则抑制中文里的机械腔（三段式、否定对举、过渡套话、客套收尾），以及时间一致性约束，让季节、天色、「上次」这类表述始终对得上真实时间。角色可以以自己的身份表达不愿意——轻则带开话头，再则说出感受，极限处直接拒绝；模型调用被提供商拦截时也以角色口吻转成一句走神，不把技术错误摆进对话
- **有状态的角色**：现场快照记下角色此刻的所在、穿着、姿态与正在做的事，跨会话与压缩都不丢，场景不再越聊越漂移；场景插件把舞台与地点记成场景记忆并延续；持有物清单记着冰箱、衣柜里有什么，做菜只用冰箱里有的食材；身体感知按各部位被触碰的累计次数划分熟悉阶段，另维护随时间回落的唤起与疲劳；心情随互动的演绎增减、随时间向平静回落；天气感知按角色与你各自所在的城市取现实天气，连同昨天与明天的概要，让角色身处的环境真的会下雨
- **表里两套人格**：由触发词切换，里人格的对话与记忆对表人格完全不可见——不仅内容读不到，条数与标题也不会露出来；两面还可以各占一条聊天通道，在 QQ 上说出暗号，接手的那一面在微信上回话
- **会记事也会忘事的长期记忆**：跨会话的事实库，索引随每轮对话注入；对话进行中定期自动提炼，历史被压缩前再提炼一次；新结论与旧记忆矛盾时就地修订并交代被推翻的旧说法；每天的对话在次日收束成一行时间线，隔几天再聊也接得上「我们最近经历了什么」；可选开启逐步淡忘——久未提及的记忆先只剩一句要点，更久之后移出记忆库（移进 `forgotten` 目录，不会真删）
- **历史检索**：按关键词与日期回查原始对话，范围含现存会话与压缩前的完整归档
- **技能手册**：把一批 SKILL.md 放进目录就能按需读取，常驻上下文的只有名称与用途，正文用到时才取——关掉角色演绎时，这是让它去干具体活儿的入口
- **会主动开口，也知道什么时候该闭嘴**：心跳按间隔唤醒模型在最近活跃的会话上说话，下次开口的时机由角色自己在对话里定——聊到兴头上挪近，你说要去睡就暂停到早上；可按情境（睡前、闲聊、干活）配多套唤醒提示词，默认内置一个「生活」情境让角色在无人时过自己的日子；外面刚下起雨、明天预报有雨这类事会成为开口的理由，下一拍提前到来；定时任务可以在对话中创建（一次性 / 周期 / 每日），到点后台执行并把结果写回会话
- **远程使用**：QQ、微信、飞书、Lark、Telegram 五条通道，各自映射一套私聊会话，支持 `/new` `/status` `/compact` `/help` 与危险操作的远程确认；后台轮次产生的回复会主动推送到远端，记忆提炼这类后台工作的说明也可选推送
- **插件化架构**：精简核心（agent 循环 / session / server / llm）+ 插件扩展，二十一个内置插件按功能分组呈现，可在设置页随时开关与配置，改动即时生效。核心只认识通用机制——提示词片段注入、会话生命周期、上下文可见域、辅助模型调用、插件自行发起轮次、操作确认、轮次过程通知、状态行、界面操作入口、只给人看的会话注记与它的旁听、轮次失败转译、插件间的依赖与冲突——它不知道「记忆」「人格」「心情」这些具体功能的存在
- **模型可配置**：提供商与模型在设置页增删改并热切换，下一次请求即生效；支持 OpenAI 兼容协议与 Anthropic Messages API
- **命令执行有人把关**：`exec_command` 采取执行前拦截并交人确认，极高危命令直接拒绝（见下），不做那种能被轻易绕过的路径沙箱
- **Web UI**：`go:embed` 内嵌单页聊天界面，SSE 流式输出，思考过程与工具调用可视化，后台任务的动静也会实时出现在会话里
- **Session 管理**：每个会话一个 JSONL 文件（首行 meta + 逐行消息），重启不丢历史
- **单一配置文件**：全部配置（含 API Key）统一在 `config.yaml`（已被 .gitignore 保护），值支持 `${VAR}` 从环境变量读取

## 快速开始

预编译的二进制在 [Releases](https://github.com/lprensoft/project-wen/releases)（windows / linux / darwin × amd64 / arm64，附 SHA256）；标着 `dev` 的那个是滚动更新的预发布，版本号形如 `v0.4.1-3-gxxxxxxx`，读作「上一个正式版之后的第 3 个提交」。也可以自己构建：

```bash
# 1. 准备配置：复制示例并填入所用提供商的 api_key（示例里是 providers.deepseek）
cp config.example.yaml config.yaml

# 2. 运行（或 go build -o wen ./cmd/wen 后直接跑 ./wen）
go run ./cmd/wen

# 3. 打开浏览器
# http://127.0.0.1:8080
```

配置文件查找顺序：`-c` 指定路径 → 当前目录 `config.yaml` → `~/.wen/config.yaml`。

```bash
wen -c /path/to/config.yaml -p 9000   # 指定配置与端口
```

## 命令

```
wen                        启动服务（等价于 wen serve）
wen serve [-c 配置] [-p 端口]  启动服务
wen config [栏目] [-c 配置]    引导式修改配置（栏目：plugins / models / server）
wen status [-c 配置]           打印当前配置与运行状态
wen version                打印版本号
wen help [命令]            显示帮助
```

`wen config` 是给**远程部署**准备的：插件的开关与参数不进 config.yaml，此前只能在 Web UI 上改，而远程机器上的 Web UI 未必方便打开。它有两种模式，进去后会在界面顶部标明：

| 服务状态 | 模式 | 行为 |
|---|---|---|
| 正在运行 | 在线 | 经服务的接口修改，**改动立即生效**，不必重启 |
| 未运行 | 离线 | 直接改配置文件，下次启动生效 |

之所以在服务运行时必须走接口：插件状态文件由服务端从内存全量重写，外部改动既不会生效，还会在服务端下一次写入时被整个抹掉。判定依据是配置目录下的 `wen.lock`（记录着实际监听地址），并实际连一次确认——进程被强杀留下的陈旧记录不会造成误判。

离线模式下插件**只登记不初始化**：读配置项声明、改开关与参数都不需要它们真的跑起来，而照常初始化会把各条消息通道的长连接、心跳与定时任务一并拉起来——用户只是想改个参数。

表单由插件自己声明的配置项生成，与设置页同源，因此新增插件时两边同时就有了配置界面。插件声明的操作也在这里：选中微信通道会出现「扫码绑定」，二维码直接以字符画在终端里（黑白不随终端配色，深色主题也能扫），码下附链接原文兜底，过期自动刷新重绘——远程服务器上不必再为扫码打开 Web UI。

## 配置说明

见 [config.example.yaml](config.example.yaml)。要点：

| 配置项 | 说明 |
|---|---|
| `model.provider` / `model.name` | 初始使用的 Provider 与模型 id（之后由设置页的「模型」栏目接管，见下） |
| `model.thinking` | 思考模式：`off` / `low` / `medium` / `high` / `xhigh` / `max`，默认 `high`（开启时 `temperature` 不生效；思考过程在 Web UI 以可折叠块展示） |
| `model.context_length` | 模型上下文窗口（token），默认 1000000；超出预算时自动从最旧对话轮次整轮裁剪；会话实测占用达到 90% 时自动压缩为摘要 |
| `server.trust_loopback` | 回环来源是否免认证，默认开启；套反向代理时必须关掉（见「远程访问与访问控制」） |
| `providers.<name>` | Provider 注册表：`type`（`openai_compat` / `anthropic`）、`base_url`、`api_key` |
| `agent.system_prompt` | 系统提示词（当前留空；运行时会自动在其前注入 `[系统环境]` 块：操作系统、Shell、工作目录、区域语言） |
| `agent.max_turns` | 单次请求内工具循环上限 |
| `agent.workdir` | 插件与环境块共用的工作目录，空 = 进程当前目录 |
| `session.dir` | 会话存储目录，默认 `<配置目录>/sessions` |

插件的开关与配置**不在 config.yaml 里**：它们由设置页维护、只存 `<配置目录>/plugins.state.json`。首次运行时按各插件声明的默认参数启用，以下十五个除外：`roleplay`、`dual_persona`（不填角色设定与触发词就不成其为功能）、`scene`、`belongings`、`body_sense`、`mood`、`presence`（自带默认参数就能工作，只因硬依赖默认关闭的 `roleplay` 而一同默认关闭）、`weather`（既依赖 `roleplay`，又要填城市才查得了天气）、`skills`（技能目录是空的，开着只多两个用不上的工具）、`heartbeat`（无人值守持续消耗额度的功能应由用户显式打开）、`qq_bot`、`wechat_bot`、`feishu_bot`、`lark_bot`、`telegram_bot`（不填凭证或不扫码绑定就没法工作）。插件自身的数据落在 `<配置目录>/plugins/<插件名>/`。

（早期版本支持在 config.yaml 写 `plugins:` 段。两处都能配的时候，哪一份在生效需要记住一条优先级规则，而设置页的改动又不回写配置文件，于是文件里的内容会慢慢变成误导。现在该段已不再生效，启动时会提示一句，可以直接删掉。）

## 模型配置（设置页 → 模型）

提供商与模型可以在 Web UI 的设置页里增删改，并切换当前使用的组合，保存后**下一次对话请求即生效**，无需重启。

- 改动写入 `<配置目录>/models.json`（权限 0600，已在 `.gitignore` 中），**不回写 config.yaml**——因为 `api_key` 里的 `${VAR}` 在解析前就被展开，回写会把明文密钥固化进文件并丢掉全部注释。
- config.yaml 的 `providers:` 与 `model:` 段是初始值：同名条目由 models.json 完全覆盖；config.yaml 里**新增**的提供商仍会出现在列表中（标记「来自配置文件」），在界面上删除它会记一条删除坠碑，重启不会复活；从未在界面上改过的条目不写进 models.json，继续跟随配置文件。
- 每个模型条目可单独覆盖 `context_length` / `max_tokens` / `thinking` / `temperature`，留空则回退到 `model:` 段的全局值。
- **注意**：`${VAR}` 展开后的密钥一旦被写进 models.json 就固定下来，此后修改环境变量不再生效。

支持两种 API 模式：

| 模式 | 说明 |
|---|---|
| `openai_compat` | OpenAI 兼容协议（DeepSeek 等） |
| `anthropic` | Anthropic Messages API。思考档位映射为 `thinking:{type:"adaptive"}` + `output_config.effort`（`off` 则为 `disabled`）；当前世代 Claude 模型不接受采样参数，故不发送 `temperature`，模型条目里的该项对 Anthropic 无效 |

Anthropic 模式下多一个**提示词缓存**开关（默认开启）：开启时把请求里不变的部分（工具、system、已有历史）标为可缓存，命中的部分按约十分之一的价格计费。代价是未命中时的写入要多付约四分之一，而缓存有效期只有几分钟——如果你的对话节奏比这更慢（比如通过 IM 断断续续地聊），关掉更省。OpenAI 兼容模式没有这个开关：DeepSeek 与 OpenAI 的缓存都是服务端自动维护的，命中与否只取决于请求前缀稳不稳定（见下文「上下文的组织」）。

## 基础工具（read_file / web_fetch 插件）

两个没什么可说的插件，放在这里只为让清单完整。都默认启用。

- **`read_file`** —— 读取本地文本文件，超出上限截断。工具同名。
- **`web_fetch`** —— 抓取网页并返回其文本内容（`fetch_url`），超时与体量都有上限。

| 插件 | 配置项 | 默认 | 说明 |
|---|---|---|---|
| `read_file` | `max_bytes` | 65536 | 单次读取返回的最大字节数 |
| `web_fetch` | `timeout_seconds` | 20 | 抓取单个网页的最长等待时间 |
| `web_fetch` | `max_bytes` | 65536 | 单个网页提取出的最大字节数 |

## 命令执行的安全机制（exec_command 插件）

这个工具把任意字符串交给 `cmd /C` 或 `sh -c`，所以它是整个系统里唯一能造成不可逆损失的地方。这里采取的是**执行前拦截并交人确认**，而不是沙箱。

**为什么不做沙箱**：shell 有 `&&`、`|`、变量展开、`for /f`、base64 解码、UNC 路径、`..\..`——想靠分析命令文本得出「它会碰哪些文件」是做不到的。一个能被轻易绕过的路径约束比不做更糟，因为用户会信它。真正的隔离要靠操作系统层面的机制（容器 / seccomp / AppContainer），而那与「在真实工作目录里跑 build、test、git」这个用途本身冲突——你得把工具链、网络、git 凭据都放进去，放完就不隔离了。真正能挡住误删的是**有人在 `rm -rf` 执行前看了一眼**，而只有人能判断意图。

三档判定：

| 判定 | 处理 | 例子 |
|---|---|---|
| 直接拒绝 | 不询问、不执行，把原因回给模型 | 整盘格式化、写裸设备、`rm -rf /`、删除系统根目录、销毁卷影副本、改 `bcdedit`、关机重启、fork 炸弹 |
| 需要确认 | 阻塞这一轮对话，界面上弹出卡片，等你点「允许执行」或「拒绝」 | 删除文件、镜像同步（会删目标端多余文件）、`git reset --hard` / `--force` / `rebase`、改权限、提权、杀进程、改服务与注册表、装卸软件包、管道进 shell、删容器与数据表 |
| 放行 | 直接执行 | 其余命令（`dangerous` 档）；只读命令（`all` 档） |

极高危的那一档刻意不询问：把「要格式化磁盘吗？」摆到人面前，本身就是一次误点击的机会。

几个实现细节：

- **串联命令逐段判定，也整条判定**。逐段是为了不漏掉藏在后半段的东西（`go build && rm -rf out`），整条是为了不漏掉本身就跨越 `|` 的模式（`curl … | sh`、fork 炸弹）。命中多个类别时全部列出——一条命令可能既删文件又改写提交历史，只说一样会让人以为自己已经看清了要同意什么。
- **拿不到答复不等于得到许可**。超时、关掉页面、连接断开，一律按拒绝处理。也刻意没有「无人值守就放行」的开关：确实要在无人值守下跑破坏性命令，请把 `guard` 关掉——那是一个看得见的选择，而不是一个容易被忘记的例外。
- **模型会被告知这条规则**，否则被拒绝的模型会去改写命令重试，那正是最该避免的行为。提示词里还要求它把破坏性操作单独执行、不要串联，这样你才能只同意其中安全的部分。

**它挡的是误操作，不是攻击**。`dangerous` 档按命令文本判断，刻意混淆（base64、变量拼接、写个脚本再执行）能绕过去。要防那个只有 `all` 一档——除只读白名单外一律确认。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `guard` | `dangerous` | 拦截档位：`dangerous` / `all` / `off` |
| `timeout_seconds` | 60 | 单条命令的最长执行时间 |
| `confirm_timeout_seconds` | 300 | 等待确认的上限，超时按拒绝处理 |

## 长期记忆（memory 插件）

会话历史不是可靠的记忆：超出上下文预算时最旧的轮次会被裁掉，实测占用达 90% 时整段历史会被**物理替换**成一条摘要。`memory` 插件在会话文件之外维护一层持久事实库。

- **存储**：一条记忆一个文件，YAML frontmatter（标题 / 摘要 / 分类 / 时间）+ Markdown 正文，可直接用编辑器增删改；手工放进去的普通 Markdown 也能被索引到。位置由 `scope` 决定：`global`（默认）存 `<配置目录>/plugins/memory/memories/`，`project` 存 `<工作目录>/.wen/memories/`。启用可见域隔离（见 `dual_persona`）后，带标签的库落在同级目录 `memories-<标签>/`。
- **索引**：每条用户消息注入一次，形如 `- 2026-05-10 约定/接口命名规范 — REST 路径用小写连字符`。索引**不落盘**，由各文件头部实时生成，因此不会与正文脱节。
- **工具**：`save_memory`（分类限 `偏好`/`约定`/`事实`/`踩坑`；默认拒绝覆盖同名条目，需显式 `mode: replace`，覆盖前留 `.bak`）、`recall_memory`、`list_memories`（可按关键词或分类过滤）、`delete_memory`。
- **自动提炼**：两条路径。一是**对话进行中**每隔若干轮真人对话（默认 10）用一次独立的模型调用提炼一次——大部分对话走不到压缩就结束了，只靠压缩那一次会白丢很多结论；二是**历史被摘要替换之前**再提炼一次，那次拿得到含工具调用的完整历史，也兜住进程重启丢掉的窗口。做成真正的提取而不是提示模型稍后自己保存，是因为自动压缩无人值守、历史随即被删，「稍后」可能永远不会到来。两条都可单独关掉，原始历史的保全由 `session_search` 的归档负责。
- **按日时间线**（默认开）：长期记忆是按主题的（偏好 / 约定 / 事实 / 踩坑），回答不了「我们最近经历了什么」——隔了几天再开口，模型只能靠检索碰运气。时间线补上这条轴：每天的对话攒进当日缓冲（不新增模型调用），新一天的第一轮对话触发一次收束，把昨天提炼成一行「日期 | 关键事件」，最近几条随对话注入。没有实质内容的一天不硬凑一行，否则很快会被「聊了聊天」填满。按可见域分文件：对话属于哪条故事线，它的时间线也属于那条。
- **矛盾修订**：提炼时会拿到已有记忆的标题**与摘要**，新结论推翻旧记忆时就地修订那一条（覆盖前留 `.bak`），并要求在正文里交代被推翻的旧说法与大致时间。给清单只看标题认不出「饮食禁忌」与「喜欢香菜」说的是同一件事，于是两条互相打架的记忆会一起留在库里——那比漏记一条更糟。
- **逐步遗忘**（默认关）：保存时可逐条标记一条记忆会不会随时间失去意义，只有标记过的才会淡忘。久未提及先把正文塌缩成那句摘要（细节没了、要点还在，也更像真实的遗忘），更久之后移出记忆库——移进库内的 `forgotten/` 子目录而不是删除，因为自动遗忘是这里唯一不可逆、且误删完全无从察觉的动作。两个时限都从**最后一次被用到**起算（读取命中、被修订、或在对话中被提到），常被提起的记忆因此永远走不到淡忘。塌缩不调模型。
- **界面上看得见**：对话进行中的提炼跑在轮次收尾之后，那时这一轮的事件流已经关闭，结果本来只能进日志。因此提炼完会在会话里留一行「🧠 记忆提炼：新增「事实/构建命令」，修订「偏好/饮食禁忌」」——实时出现、可事后回看，而**模型永远看不到它**。修订尤其需要说出来：它会覆盖已有记忆，虽然留了 `.bak`，但没人会想到去翻。

**索引开销**：索引在一次工具循环的**每一轮**都会完整发送（系统消息永不被上下文裁剪），因此有硬上限。实测一条约 31 token，100 条约 3100 token。超出字节上限时先省略各条摘要只留标题，仍超出才按最近更新截断并注明剩余条数——优先保住标题，模型才知道这条记忆存在、还能按名读取。

## 历史检索（session_search 插件）

`memory` 存的是提炼过的结论；要回查当时的原话则用本插件。两者互补：记忆信噪比高、常驻提示词，原始对话保真但噪音大、按需检索。

- **工具**：`search_sessions`（关键词 + 日期范围，一次覆盖现存会话与压缩归档）、`read_session`（读某个会话，可按关键词或日期收窄）、`read_archive`（读某份归档全文；不传文件名则列出全部）。
- **压缩归档**：历史被摘要替换**之前**，完整原文（含思考过程与工具调用）原样写入 `<配置目录>/plugins/session_search/archives/`，并在摘要末尾留一行归档位置。只做文件写入，不发起模型调用。**被压缩过的会话在现存文件里只剩一条摘要，归档是其原文唯一的去处**，因此检索必须覆盖它，否则最值得回查的部分正好成了盲区。
- **日期筛选的坑**：会话 id 与 `Meta.CreatedAt` 是**创建**时间，而会话会跨天继续使用，所以不能只看文件名判断日期——实际按每条消息的 `ts` 过滤。两个方向的剪枝是安全的：文件修改时间早于起始日的可跳过（追加消息会更新文件时间），创建时间晚于结束日的可跳过（消息不会早于会话创建）。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_scan_sessions` | 300 | 单次最多读取的会话数，按时间从新到旧；超出会在结果里注明 |
| `max_snippets` | 3 | 每个会话最多返回的摘录数 |
| `max_bytes` | 8192 | 单次返回上限 |
| `max_archives` | 20 | 保留的压缩归档数，0 = 不归档；按可见域各留这么多份 |

## 技能手册（skills 插件）

外面那套「技能」——一批用户自己安装的 SKILL.md，模型按需读取——在这里就是一个普通插件，核心不为它加任何东西。默认不启用（目录是空的，开着只多两个用不上的工具）。关掉角色演绎那组插件时，这是让它去干具体活儿的入口。

- **目录结构**：技能目录下每个子目录一个技能，里面放一份 `SKILL.md`，头部用 YAML frontmatter 写 `name`（可省，默认取目录名）与 `description`（必填，缺了这条不加载——没有用途说明，模型无从判断什么时候该读它）。目录名限小写字母、数字、连字符与下划线。
- **常驻的只有清单**：系统提示词里放的是「名称 + 用途」一行一条，正文一个字都不放。超出条数上限的不会消失，模型用 `list_skills` 看得到完整清单。
- **正文走工具返回值**，这是刻意的：按需加载意味着内容会在第 N 轮才出现，塞进系统提示词或每轮状态块都会让整段前缀作废、提示词缓存全部落空；而工具结果是追加进历史的，此后前缀不再变动。
- **工具**：`read_skill`（读某个技能的正文，超上限截断）、`list_skills`。
- **改完目录点一下扫描**：设置页齿轮里有「重新扫描技能目录」，会报出解析到几个、哪些没加载成功以及原因，说明文字里也带着当前生效的完整目录路径——不然「我的技能怎么没出现」只能靠猜。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `dir` | 空 | 技能目录，留空用 `<配置目录>/plugins/skills/` |
| `max_list` | 30 | 常驻清单最多列出的条数 |
| `max_bytes` | 32768 | 读取单个技能正文的返回上限 |

## 角色扮演（roleplay 插件）

把用户配置的角色设定、台词样例与用户自己的信息作为最高优先级提示词注入，并附几套表达纪律。默认**不启用**——它会显著改变模型的行为方式，应由用户主动打开。硬依赖 `memory` 与 `session_search`：一个有连续性的角色需要记得住跨会话的事、查得到之前说过的原话，缺了这两样，角色每开一个新会话就重新变成陌生人。

注入的各段（都可单独关掉，配置为空则整段不注入）：

- **`[角色设定]`** — 声明优先于其它一般性指令；不说明自己在扮演，不跳出角色做解释。
- **`[台词样例]`** — 角色实际说话的样例，用来锚定语气。性格描述说「毒舌但嘴硬心软」，模型理解出来的腔调千人千面；三五段一来一回的真实对话，比任何形容词都管用。建议覆盖不同情绪的场合（高兴时、被烦到时、认真说事时），开了【】演绎就在样例里也带上【】。提示词里注明样例里的人和事只是示范，不会被角色当成真实经历。
- **`[对方信息]`** — 设置页上叫「我的信息」，作为角色一开始就知道的信息，并要求对话中得知的新信息以对话为准、用 `save_memory` 存下来。因此这一项可以留空，直接在对话里告诉它即可。（界面与提示词的人称是相反的：填的人是你，而提示词是模型以第一人称读的，那里的「我」指它自己，所以注入的段落写作「对方」。）
- **`[互动演绎]`** — 每次回复以一段 `【】` 开头，先写此刻的场景、动作与表情，再写角色说的话。`【】`里只写能被观察到的东西；场景必须承接历史中最近一处`【】`给出的位置、姿态与氛围，不凭空转场；一轮回复中可以多次插入，让动作与对话交替推进而不是把动作全堆在开头。
- **`[边界与感受]`** — 让角色有能力说「不想」。一个从不拒绝的存在没有内在，关系的真实感恰恰由边界撑起来。这里只给表达的层次与方式：轻则顺着话头把方向带开、不点破；再则以第一人称说出此刻的感受与请求（「等一下」「今天不太想说这个」）；极限处直接拒绝，「我不想」本身就是完整的理由。硬性要求是拒绝永远从感受出发、不出现规则条款式的措辞、不跳出角色解释为什么不行，并且前后一致——上次明确不愿意的事，这次不会无缘无故就愿意了。边界划在哪里由角色设定与当下的演绎决定，插件不替角色划线。
- **`[体型与动作]`** — 仅当角色设定与我的信息**都**给出身高时注入：视线高低、俯身还是抬头、伸手能否够到，都按实际差值写。只有一方给出时不注入，避免凭空假设。
- **`[自然表达]`** — 抑制中文里真正会暴露机械感的模式：三段式、否定对举（「不是 X，而是 Y」）、强凑三项并列、过渡套话、无来源的「专家认为」、宣传腔形容词、emoji、滥用加粗、客套收尾、谄媚开场、过度对冲。这一段只约束话语部分，`【】`里的演绎有自己的笔调。思路取自 [blader/humanizer](https://github.com/blader/humanizer) 的 AI 文风模式清单，但按中文语境重写——英文特有的那些（em dash、Title Case、弯引号、`delve` 之类的词）对中文输出没有意义。
- **`[记忆与回想]`** — 两件事：给保存下来的记忆标上会不会淡忘、结论被推翻时修订旧记忆而不是另存一条；以及不去翻历史对话的原文复述细节，被提起时按「想起来」的样子说要点，记不清就直说。后一条不加，遗忘就是白做的——记忆淡忘了、归档了，模型照样能用 `session_search` 把当时的原文一把捞出来逐字念一遍。出戏的从来不是「想起来了」（被提醒后能回想起来本就是人的特征），而是想起来的方式。
- **`[时间一致性]`** — `<本轮状态>` 里的当前时间是唯一可信基准，历史对话里出现过的时刻只是当时的「现在」；同时明确环境块的其余项（操作系统、Shell、工作目录）只是运行环境事实，不构成角色的自我认知。不加这条，模型会被那个块稳定地拽回「我是一个跑在 Windows 上的助手」。

另有两个钩子：

- **压缩前保住场景**：把**最后一处`【】`的原文**留在摘要末尾（摘要会丢掉场景与姿态这类细节，压缩一次场景就断了）。距上次对话的间隔由核心每轮给出（见下文「上下文的组织」），这里只负责说清间隔长了该怎么演。
- **失败转译**（默认开）：模型调用失败——最常见的是内容被提供商的安全策略拦截——时，不把厂商的原始错误怼给正沉浸在对话里的人，而是用一次辅助调用以角色口吻生成一句走神般的停顿（连这一句也生成不了时用兜底台词），拒绝显现为角色的状态而不是系统的墙。原始错误由核心转入会话注记，界面上仍看得到，真相不丢。配置类错误（密钥、地址，401/403/404）原样报出，那类问题只有看到原文才修得好。只在真人在场的轮次转译，心跳这类后台轮次失败就是失败。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `persona` | 空 | 角色设定（多行）。留空则只保留下面几项规则 |
| `user_profile` | 空 | 我的信息：你的基本情况（多行）。可留空，改在对话中告知 |
| `voice_samples` | 空 | 台词样例（多行），段与段之间空一行 |
| `interaction` | 开 | `【】`互动演绎 |
| `boundaries` | 开 | 边界表达 |
| `humanize` | 开 | 自然表达规则 |
| `time_rules` | 开 | 时间一致性约束 |
| `memory_rules` | 开 | 记忆与回想约束 |
| `translate_failures` | 开 | 失败转译，需要已填写角色设定 |
| `failure_line` | 内置 | 转译的兜底台词 |
| `max_text_bytes` | 8192 | 角色设定、我的信息与台词样例的合计上限，超出时按 设定 > 我的信息 > 样例 的顺序保留 |

## 表里人格（dual_persona 插件）

表人格用 `roleplay` 的设定，里人格另设一套。**里人格的对话、记忆与归档对表人格不可见，里人格看得到全部。**默认不启用，硬依赖 `roleplay`。

- **切换**：两个多行文本框各配一组触发词，一行一个。命中的那条消息**照常发给模型**、由新人格作答，界面上不做任何提示。切换对当轮即时生效，因此表→里的暗号不会留在表人格的历史里；反过来，里→表的暗号会进入表人格可读的历史（见下方「按整轮分配」），建议选一个在表人格语境下也说得通的说法。两个方向同时命中时回表人格优先，避免卡在里人格出不去。
- **状态延续**：每个会话各记一条人格状态，切回旧会话按它恢复；新建会话继承上一次对话的人格。状态存在插件自己的目录里而不是从历史反推——压缩会按可见域重排消息，反推会给出错误答案。
- **隔离范围**：对话历史（按可见域过滤）、记忆（按域分库，表人格读不到里人格的条目，连条数与「已存在同名记忆」这类报错都不会泄漏）、会话检索与归档（按域过滤，会话标题也带归属，不可读时显示 `(无标题)`）、压缩摘要（按域分组，每域一条带标签的摘要）。
- **分通道**（可选，默认关）：两面各占一条 IM 通道，回复发往当前人格所属的通道，与你从哪条通道说话无关——在 QQ 上说出暗号，接手的那一面在微信上回你；在微信上说切回的暗号，回复落回 QQ。心跳、定时任务这类后台轮次同样跟着人格走。选中的通道必须已启用，且你在那边先跟机器人说过话（投递时会把那位用户接到当前会话上，他原先的会话不再是当前会话）。投不出去的那一段回复**直接丢弃**，只在会话里留一行说明——回落到来源通道等于把另一面的话直接摆到这一面眼前，正是要防的事。那段话本身仍在会话文件里，Web UI 翻得到。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `inner_persona` | 空 | 里人格设定（多行），只在里人格激活时注入 |
| `inner_voice_samples` | 空 | 里人格台词样例（多行）。表人格配了样例时这里最好也配一份，否则里人格的腔调容易被表人格的样例带跑 |
| `to_inner` | 空 | 切到里人格的触发词，一行一个 |
| `to_outer` | 空 | 切回表人格的触发词，一行一个 |
| `match_mode` | `contains` | `contains` 消息里出现即命中；`equals` 整条消息就是该词才命中 |
| `split_channels` | 关 | 表里人格分通道总开关 |
| `outer_channel` | 不指定 | 表人格所在通道，从已有的 IM 通道里选 |
| `inner_channel` | 不指定 | 里人格所在通道 |
| `max_text_bytes` | 8192 | 里人格设定与台词样例的合计上限，超出时优先保留设定，样例按段丢弃 |

> **这是上下文隔离，不是沙箱。** `read_file` 与 `exec_command` 是通用的文件与命令通道，能直接读到会话文件、记忆目录与本插件的状态文件，绕过一切提示词与工具层过滤。本插件把这两个声明为冲突项，同时启用时设置页会给出告警，但不阻止——你可能确实要一个能干活的角色，代价自己权衡。

## 场景感知（scene 插件）

角色要有连续的处境，光有性格不够——上一次在哪、那间屋子什么样，模型从对话历史里看不出来，压缩一次更是全没了。本插件把**舞台设定**（用户配置的固定环境）与**场景记忆**（对话中出现过的地点）分开：前者每轮全额注入，后者按可见域从库里取。默认不启用，硬依赖 `roleplay`——没有角色，舞台没有站的人。

- **两段注入**：`[场景与环境设定]` 是你写死的舞台，只读不改；`[场景感知]` 是记录判据，要求把对话里出现的城市、街区、建筑、房间、店铺或反复出现的活动场所记下来，并明确「只记场景本身——位置、与其它地点的关系、布局、陈设、氛围，不记一次性的动作与对话」。
- **先查再记**：判据里要求记录前先看 `[场景记忆]` 里有没有同一地点，已有且一致就不再记，有补充或变化用 `replace` 更新原条目而不是另建一条。否则同一间屋子会攒出好几份互相矛盾的描述。
- **工具**：`save_scene`、`list_scenes`、`delete_scene`。库存在 `<配置目录>/plugins/scene/scenes/`，启用可见域隔离后带标签的库落在同级的 `scenes-<标签>/`。
- **注入有上限**：场景记忆随每轮对话重复发送，超出字节上限时先省略描述只留名称，仍超出才截断——与记忆索引同一套降级思路，优先保住「有这个地方」这件事。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `stage` | 空 | 场景与环境设定（多行）。留空则只保留记录能力，不注入固定舞台 |
| `max_scenes` | 30 | 注入的场景条数上限，超出按最近更新保留 |
| `max_inject_bytes` | 8192 | 场景记忆的注入字节上限 |

## 天气感知（weather 插件）

外面在下雨还是刚放晴，是一条持续起作用的背景——它不构成话题，但影响环境的样子、人的状态和关心的方向。本插件按设定的城市定时取现实天气（数据源 [Open-Meteo](https://open-meteo.com/)，免费、无需密钥），把此刻的天气每轮注入。默认不启用，硬依赖 `roleplay`。

它注入的是**环境状态**而不是一个可调用的工具，这也是它归在「角色演绎」而不是「基础工具」的原因：通用对话里每轮塞一行天气只是噪声，真要问天气，模型自己用 `fetch_url` 抓就够了。

- **天气首先得是角色自己的**。只给「你所在地的天气」时，那是一条关于第三方的信息——角色对它既没有体感也没有可做的反应，于是在对话里几乎不起作用。所以这里分角色与用户两处地点，同城时合成一处，代入感最强。
- **两种天气有两种用法**，注入的准则分开写：**自己那边的天气进入环境与状态**——光线、声音、冷热、开不开窗、出门方不方便，写进场景与动作的描写里，被感觉到而不是被谈论（不需要说「今天下雨」，写雨声、写潮气就够了），也自然地影响语气与精神头；**对方那边的天气是一件你知道的事**，用于关心的方向，不当开场白。
- **带上昨天与明天**：同一次请求顺带取回昨天与明天的概要（零额外调用），接在现况之后注入。做注入而不是工具，是因为真人不「查」明天的天气——他早上瞟过一眼预报，聊到明天时顺口就知道，昨天则是记得，这两样都是环境常识。准则里明天只是预报，措辞留有余地；按日期核对而不是信字段名，跨过午夜后缓存里的「明天」其实是今天，对不上的那天不注入。
- **天气是开口的理由**：每次刷新后对比前后两次观测，现况里降水的开始或停止、明天的预报里出现降水，都会投递一条开口理由（见「心跳」），由心跳带进主动开口的轮次——「刚下起雨了」「明天有雨，记得带伞」比任何无话找话都像真人。只报转变不报状态，状态本来就每轮注入；前一次观测太旧（宕机横跨）不报，那时说「刚下起来」就是错的；明天有雨只在第一次看到时投，雨从预报里消失时撤回还没说出口的那句。
- **同城只查一次**：开着「与我在同一个城市」时只按角色的城市取数。两处填了同一个地名也会自动合并——否则会注入两行一模一样的天气。
- **不填城市就什么都不注入**，包括那段讲天气怎么用的规则。虚构或历史舞台就该是这个状态：留空，或干脆关掉插件。
- **舞台优先**：`[场景与环境]` 设定的舞台不是这里给出的地方时，以舞台为准，天气不参与场景描写。
- **后台刷新，注入只读缓存**：`TurnPrompt` 在每轮对话的同步路径上，在那里发网络请求就是让每一轮都替一次超时买单。
- **过期就不注入**：取不到新数据时，让角色不知道天气，好过把三小时前的天气当成此刻。因此过期时限不得小于刷新间隔——否则刚取到的也立刻算过期，等于永远不注入。一边取到一边取不到时，注入取到的那一边。未收录的天气代码回落到「天气不明」，注入的内容宁可含糊也不能是错的。
- **测试按钮**：设置页齿轮里有「测试这些城市」，读的是**还没保存**的输入，把每一处解析成了哪个地方、当时的天气是什么都列出来；一处失败也会把另一处的结论一并给出。
- **状态行**把「没配城市」「取不到」「过期了」分开报，过期标在具体那一处上——两处地点时，一处失效不代表另一处也没在用。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `persona_location` | 空 | 角色所在的城市。主要的那一个，角色自己那边的天气才会进入它的环境与状态 |
| `same_city` | 开 | 与我在同一个城市。开启时只查上面那个城市，下面一项不生效 |
| `user_location` | 空 | 我所在的城市，作为角色知道的一件事。仅在上一项关闭时生效 |
| `refresh_minutes` | 30 | 后台刷新间隔（分钟），最快 10 分钟 |
| `stale_minutes` | 60 | 距上次成功取得超过这么久就不再注入，不得小于刷新间隔 |

## 持有物（belongings 插件）

冰箱里有什么、衣柜里有几件外套，模型从对话历史里只能翻到只言片语，压缩一次就全没了，于是上周买的菜这周还在，昨天说吃完的鸡蛋今天又能炒。本插件把持有物记成按容器分的清单（冰箱、衣柜、书架……每类一个容器），每轮注入，演绎与它保持一致：做菜只用冰箱里有的食材，穿衣只从衣柜里挑，清单里没有而剧情需要的东西先经历取得再使用。默认不启用，硬依赖 `roleplay`。

- **只记「现在有什么」**：穿上脱下、拿起放下不改清单；物品的来历与意义（谁送的、为什么买）值得长期记住时另存为记忆。可数的物品带数量（鸡蛋×6），消耗时报减少的数量，减到 0 自动移除。
- **物品会变旧**：每件物品带放入时间，隔久了的标着「N 天前放入」，食材该不该扔由模型在演绎里自然处理并同步更新清单。
- **工具**：`update_items`（add 放入 / remove 取出或消耗，同一容器的变化合并成一次调用，容器不存在时自动新建）、`list_items`（可按容器或关键词过滤）。按可见域分库存放。
- **有上限**：容器数与单容器物品数都有限，超出拒绝放入并提示先清理——清单不该长成仓库账。注入同样有字节上限，超出先省略物品只报件数，仍超出只注明容器数。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_containers` | 10 | 容器数量上限 |
| `max_items` | 50 | 单个容器的物品上限 |
| `max_inject_bytes` | 4096 | 清单的注入字节上限 |

## 身体感知（body_sense 插件）

同一处接触在第一次和第二十次不该是同样的反应，但模型没有跨会话的计数，于是每次都从零开始演。本插件按部位记累计次数，划成熟悉阶段，把状态与「不同阶段该是什么取向」的准则一起注入。**插件只提供机制与状态，不写台词**——具体怎么演由角色设定决定。默认不启用，硬依赖 `roleplay`：没有角色，身体就没有归属。

- **两个正交的维度**：熟悉度（累计次数 → 初次 / 生疏 / 适应 / 熟悉 / 习以为常）与私密度（日常 / 亲近 / 亲密 / 私密四档）。私密度不参与熟悉度计算，只随状态注入——它决定「起点多强烈」与「衰减到什么程度为止」，熟悉度决定「衰减了多少」。合成一个阈值等于用一个维度表达两件事，两边都表达不好。
- **部位表可改**：四档各一个多行文本框，一行一个部位。内置的默认表按「在什么关系阶段才会自然发生」分档而不是按解剖学：「手」与「手指 / 手背 / 手腕」分开（牵手、碰指尖、握手腕是三种强度），「腰」放在亲密档（中文语境里搭腰是明确的亲密动作），不分左右（分了计数摊薄一半而叙事上从不区分），私密档只留三条（条目越多模型越倾向往这一档上报，而这一档误报的代价最高）。
- **即时身体状态**：唤起与疲劳各 0-100，补的是接触计数（长期熟悉度）与心情之间缺的那层——「此刻身体是什么状态」。由模型按演绎报变化量（`adjust_body_state`，一轮最多一次，两项可同时报），随时间各按各的速度向 0 回落，回落的过程本身就是余韵与恢复，不单设状态。落盘在会话之外，跨会话天然接力。按可见域各存一份，读取时对可读域逐字段取最大值——不学心情的「各域完全独立」：心情属于人格，身体是同一具。
- **工具**：`record_touch`（记下接触并回显累计次数与阶段，判据要求「先记录、拿到回显、再写这一处的反应」）、`list_body_state`、`adjust_body_state`。
- **一键重置**：设置页齿轮里有「清空接触记录」与「重置身体状态」，都含各人格分开保存的那几份。不可撤销。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `parts_daily` / `parts_close` / `parts_intimate` / `parts_private` | 内置表 | 四档部位表（多行，一行一个）。部位名随工具声明每轮发送，超量报错而不截断——被截掉的部位模型看不见，你却以为配上了 |
| `familiarity_pace` | 中 | 阶段推进的快慢：慢（次数减半）/ 中 / 快（次数加倍）。中档下 1 次为初次、2-3 生疏、4-9 适应、10-19 熟悉、20 以上习以为常 |
| `arousal_decay_per_hour` | 30 | 唤起每小时向 0 回落的点数，0 = 不回落 |
| `fatigue_decay_per_hour` | 10 | 疲劳每小时向 0 回落的点数，0 = 不回落 |
| `state_max_delta_per_call` | 30 | 单次调整唤起或疲劳的上限，超出按上限收并告知模型 |
| `max_inject_bytes` | 2048 | 接触记录的注入字节上限；超出时先省略次数只留阶段，再按阶段归并 |

## 心情（mood 插件）

角色的状态应当被互动改变，也应当自己平复。心情值范围 -100 到 +100，0 为平静，由模型在被夸、被冷落、玩笑开过头、久别重逢这类事发生时主动上报变化量，并随时间向平静回落。默认不启用，硬依赖 `roleplay`。

- **先调整、再演绎**：判据里这一条不能省。心情注入发生在轮次开始，工具回显要到模型写完话才到达；不先调工具的话，被说了重话的那一轮仍然按上一轮的好心情在回应，情绪要迟一拍才落下来。
- **报变化量而不是目标值**：好一点是 +10，很难过是 -35。一轮最多调一次，把这一轮的事合起来算。
- **心情只改表达，不改角色**：注入的准则明确心情影响的是话多话少、主动被动、动作松紧，而不是角色是谁、也不是事实与立场；并要求不要把心情当结论说出来（不出现「我现在心情是 -30」这类话，也不报数值）。
- **随时间回落**：按每小时若干点向 0 靠拢，因此不需要为「过了一阵子该好些了」专门调整。填 0 表示不回落，心情会一直停在上次的值。
- **工具**：`adjust_mood`（报出变化量，回显调整后的心情）。
- **一键重置**：设置页齿轮里有「重置为平静」，含各人格分开保存的那几份。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `decay_per_hour` | 5 | 每小时向平静回落的点数，0 = 不回落 |
| `max_delta_per_call` | 30 | 单次调整的绝对值上限。改小让情绪变化平缓，避免一句话就从开心跌到谷底 |

## 现场状态（presence 插件）

场景与姿态此前只能靠模型翻历史里最近一处`【】`演绎来延续，历史一压缩、会话一换，现场就断了，于是穿着越聊越漂移、明明在厨房下一句坐在了床边。本插件把角色此刻的**现场**记成一份快照——所在地点、穿着、姿态与相对位置、正在做的事、持续生效的状态（「只开了床头灯；窗开着一条缝」）、当前感官焦点——作为 `[当下状态]` 排在本轮状态块的**最后**、离生成位置最近，演绎从那里继续。没有配置项。默认不启用，硬依赖 `roleplay`。

- **只传变化的字段**：`update_presence` 非空值覆盖该项、空串清除该项、没提到的保持原样；现场变化时（换了地方、脱了外套、灯灭了）随手更新，一轮至多一次。
- **隔久了的字段会标时间**：超过半小时没动的字段标着「N 前记下」，给模型一个判断「这项是否已自然失效」的线索（睡了一觉，昨晚的姿势就不作数了），又不让每行都挂着时间戳。
- **只记可观察的现场事实**，不写情绪与心理活动——那是 `mood` 的事。按可见域各存一份。
- **一键清空**：设置页齿轮里有「清空现场状态」，含各人格分开保存的那几份。不可撤销。

## 心跳（heartbeat 插件）

让角色会主动开口。按间隔唤醒模型，在**最近活跃的会话**上跑一轮完整对话（带系统提示词与全部启用插件的提示词），输出直接落进那个会话。默认不启用——无人值守持续消耗额度的功能应当由用户显式打开，而不是装上就开始花钱。

- **心跳自己不算「活跃」**：落点只看真人交互过的会话（Web UI 与各条消息通道的轮次），否则心跳会不断把自己认成活跃、无限自我续命。
- **不打断聊天**：真人说完话后倒计时从此刻重新开始。心跳是「没人说话时才主动开口」的机制，聊天途中插进来既打断对话，也让间隔配置失去意义。
- **节奏由角色自己定**（默认开）：模型手上有一个 `set_heartbeat_interval` 工具，聊到兴头上就把下次开口挪近，你说要去忙就往后推，定完倒计时从此刻重算。它是在对话中顺手调用的，因此不产生任何额外的模型调用；理由也随调用一起写下来，落在日志里。当前节奏每轮亮给模型一行——看不见现状，「话题正热该调快」的判据永远不会触发。
- **可以真正睡觉**：`pause_heartbeat` 暂停主动开口一段时间（最长一天，睡一夜按七到九小时报），到点恢复常规节奏，你一说话立即恢复。暂停期间空闲衰减不计数——这段安静是角色自己定下的，不是「没人想聊」的证据。暂停到点的第一拍视为「睡醒」，节奏回到基础值。
- **往慢与往快都有自动通道**：没人说话时空闲衰减每 15 分钟把间隔放缓一档（×1.5）直到最慢间隔，不必等模型想起来调；真人一来，慢于基础值的节奏机械恢复到基础值（衰减攒出来的慢速与「她今天忙」式的过时安排就地作废），快于基础值的设定保留——热聊中调快的节奏不被一条新消息打回去。两边都零模型调用。间隔一律取整到分钟，并收进你设的上下限。
- **有事才说，不是到点就说**：心跳同时是「开口理由」公告板的消费方。别的插件投递了值得主动说的事（天气刚下起雨、明天预报有雨）时，下一拍提前到最快间隔，理由随心跳提示词一并交给模型，说不说、怎么说仍归模型；暂停压过一切——睡着的人不为一场雨叫醒。轮次失败时理由放回公告板等下一拍，过期的自动作废（「刚下起雨」两小时后说出口就是错的）。公告板只在内存里：重启丢掉的只是「尚未说出口的那一句」，仍然成立的理由会被产生方的下一次检测重新发现。
- **按情境换提示词**：同一套心跳模板每次醒来都说一样的话，机械感正来自于此。可按情境配多套（`[睡前]` `[闲聊]` `[干活]`……），模型在调整节奏或暂停时顺手声明当下的情境，下次心跳就用那一套——「睡前暂停到早上、醒来用早安的说法开场」是一个动作。默认内置一个「生活」情境作范例：先过日子（更新自己的场景、心情这类状态，幅度与实际过去的时间相称），再决定要不要开口，无话保持安静——两次对话之间角色不该是冻结的。可改可删，清空后不会长回来。
- **隔久了先回顾再开口**：距上次对话超过 12 小时（心跳本来就慢的人按更长算）的唤醒附一句重定向：先回顾已保存的记忆与最近经历，再决定要不要开口、说什么，不要顺着久远的上文接话——顺着接只会显得没睡醒。
- **关掉动态心跳**就是固定间隔，模型也改不动：此时调用那两个工具会被拒绝，并告诉它去哪儿打开。
- **提示词是一次性输入**：心跳的提示词只在它自己那一轮发给模型，不进入后续上下文、不进压缩摘要、不参与会话标题，界面上渲染成一行来源提示而非用户气泡。助手的回复照常保留。末尾会自动附上「距上次对话过去了多久」。
- **状态行**：`/status` 里的心跳一行报当前节奏、情境与下次时机，暂停期间改报恢复时间。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `interval_minutes` | 30 | 基础间隔；关闭动态节奏后即为固定间隔 |
| `prompt` | 内置 | 心跳提示词（多行），可改成任何内容 |
| `dynamic` | 开 | 允许模型自己定下次开口的时机或暂停一段时间，并在无人聊天时逐步放缓；关掉则固定按基础间隔 |
| `context_prompts` | 内置「生活」范例 | 情境提示词（多行）：以「[情境名]」单独起一行，之后的行是该情境的内容，可写多段；说「默认」切回上面的提示词。清空则始终用上面的提示词 |
| `min_minutes` / `max_minutes` | 5 / 120 | 动态调整的上下限；模型报出的值超出范围时会被收进来并如实告知 |

## 定时任务（scheduler 插件）

模型可以在对话中创建定时任务（一次性 / 周期 / 每日），到点由后台跑一轮对话，结果写进最近活跃的会话——落点判定与心跳相同。默认启用。

- **任务不在调度循环里跑**：每个到期任务单独开 goroutine，带 recover 与 15 分钟超时，单个任务卡死或崩溃不影响主程序与其它任务。
- **撞上会话忙**：一次性任务按分钟重试，最多 5 次；周期任务直接跳过等下个周期——后台任务堆在锁上，只会在解锁瞬间连环轰炸同一个会话。
- **宕机期间错过的**：一次性任务在 24 小时以内补跑，超过则标记为过期而不是突然执行一件早已无意义的事。已完成的任务保留 24 小时供 `list_tasks` 查看。
- **防失控**：任务总数上限 200，超过后拒绝新建。
- **顺手记下将来的事**：提示词里引导模型在对方随口提到将来的事（周五要面试、下周去旅行）时定一次性任务，到时主动提起——用工具顺手表达，零额外开销。
- **工具**：`schedule_task`、`list_tasks`、`cancel_task`。

## 远程使用（qq_bot / wechat_bot / feishu_bot / lark_bot / telegram_bot 插件）

五条通道，都把一个远端用户映射成一个普通会话——远程会话就是普通会话，Web UI 刷新即可看到，两边聊的是同一份历史。默认都不启用。

通道无关的部分（入站分发与去重、命令集、按用户串行、会话绑定、确认代理、推送）只有一份实现，各插件只负责自己的协议层，所以下面这些约定在五条通道上完全一致：

- **命令集**：`/new` 开新会话、`/status` 看模型与用量、`/compact` 手动压缩、`/help`，以及危险操作确认的 `/apply` / `/deny`。
- **白名单之外一律拒绝**，只记日志。白名单为空时拒绝所有人；陌生用户的 id 会写进日志，方便你抄进白名单。
- **危险操作可远程确认**：`exec_command` 需要确认时，请求推到远端，等 `/apply` 或 `/deny`；超时按拒绝处理。拿不到答复不等于得到许可。
- **后台轮次会推送**：心跳、定时任务这类后台轮次落在绑定的会话上时，助手的最终文本会主动推给远端——否则结果只进会话文件，你在手机上永远看不到。前台轮次、自己发起的轮次、以及**由别的通道发起的轮次**都不推，那些各有回复渠道。
- **过程可选转发**：「展示思考过程」与「展示工具调用」默认都关。工具只转发名字，参数与结果可能载有隐私。
- **后台通知可选推送**：「推送后台通知」（默认关）把记忆提炼这类后台工作留在会话里的说明原文推给绑定用户，与 Web 界面看到的一字不差，推送本身不写入会话。只推插件后台工作产生的：带可见域标签的（归属拿不准，宁可少推也不把一面人格的动静泄漏到另一面）、前台轮次的旁注（如失败转译留下的报错原文——前门为沉浸感藏起的东西不从边路漏出去）、IM 通道自己发的操作者旁注，都不推。
- **可以按人格分流**：开启 `dual_persona` 的分通道后，回复发往当前人格所属的那条通道，与你从哪条通道说话无关（见「表里人格」）。

各自的协议层：

| | 通道 | 凭证 | 要注意的 |

## 远程访问与访问控制

部署到远程服务器时，Web UI 的未授权访问不只是「聊天记录被看到」：`exec_command` 能执行命令、`read_file` 能读任意文件，而改掉某个提供商的 `base_url` 再触发一次请求就能把 api_key 送到别处。所以它默认只监听 `127.0.0.1`。

**认证按请求来源判定，不按监听地址判定**：

| 来源 | 行为 |
|---|---|
| 回环地址（`127.0.0.1` / `::1`） | 免认证。本机运行全程无感，不需要设任何口令 |
| 其它来源 | 需要访问口令，登录后由 Cookie 维持会话（7 天滑动过期，进程重启失效） |

口令存于 `<配置目录>/auth.json`（0600，只存 PBKDF2-HMAC-SHA256 派生值，不存明文），**不写进 config.yaml**——那个文件永不回写。

### 新装的机器怎么设第一个口令

配了对外监听却还没设口令时，服务**不会拒绝启动，而是降级为只监听 `127.0.0.1`** 并在日志里说明。这样永远不会出现「服务不可达且没法配置」的死局，同时一次都没有暴露过。补口令有三条路：

```bash
# 1）在服务器上直接配（推荐）
wen config server

# 2）SSH 隧道 + Web UI：隧道进来的请求源是回环，免认证，
#    打开界面后在设置页的「访问控制」里设置口令
ssh -L 8080:127.0.0.1:8080 <用户>@<服务器>

# 3）容器 / 自动化部署：环境变量优先于 auth.json，且界面上改不动
WEN_AUTH_PASSWORD=<口令> wen
```

设好口令后重启，配置里的 `host` 才会真正生效。

### 几条要注意的

- **套反向代理必须把 `server.trust_loopback` 关掉**。那种部署下所有请求都从回环地址进来，开着等于没有认证。程序刻意不读 `X-Forwarded-For`：请求头谁都能伪造，拿它当认证判据比不做认证还危险。
- **TLS 不由本程序提供**。明文 HTTP 上传口令等于没有认证，请让它跑在 SSH 隧道、WireGuard/Tailscale 组网或反向代理之后。
- **跨站写请求一律拒绝**（校验 `Origin` 与 `Host` 一致），本机部署同样受这层保护——否则任意网站都能让你的浏览器向 `127.0.0.1:8080` 发起写请求。
- 登录失败按来源 IP 限速（5 分钟内 5 次）。
- 改口令会让所有已登录会话失效，包括发起修改的那个。

### 升级提示（破坏性变更）

此前配了 `host: 0.0.0.0` 的实例，升级后若未设置口令会降级为只监听本机。这是有意的：那些实例此前处于完全开放状态。按上面任一条设置口令并重启即可恢复对外服务。

## 服务器部署（Linux）

两种方式：临时或简单场景用启停脚本，长期跑用 systemd（开机自启、崩溃自动拉起、journald 管日志）。两者的共同点：**工作目录必须是 `config.yaml` 所在目录**——wen 从工作目录读配置，会话与插件状态也落在由它推导的目录里，目录不对的表现是「像全新安装一样什么配置都没有」。

### 启停脚本

放在 wen 二进制与 `config.yaml` 同目录，保存为 `wen.sh` 并 `chmod +x wen.sh`：

```sh
#!/bin/sh
# wen 启停脚本：./wen.sh {start|stop|restart|status}

cd "$(dirname "$0")" || exit 1

PIDFILE=./wen.pid
LOGFILE=./wen.log

running() {
    [ -f "$PIDFILE" ] && kill -0 "$(cat "$PIDFILE")" 2>/dev/null
}

start() {
    if running; then
        echo "wen 已在运行（pid $(cat "$PIDFILE")）"
        exit 0
    fi
    nohup ./wen >>"$LOGFILE" 2>&1 &
    echo $! >"$PIDFILE"
    sleep 1
    if running; then
        echo "wen 已启动（pid $(cat "$PIDFILE")），日志: $LOGFILE"
    else
        rm -f "$PIDFILE"
        echo "启动失败，最近日志："
        tail -n 20 "$LOGFILE"
        exit 1
    fi
}

stop() {
    if ! running; then
        echo "wen 没有在运行"
        rm -f "$PIDFILE"
        return 0
    fi
    pid=$(cat "$PIDFILE")
    kill "$pid"
    # 等最多 10 秒让它优雅收尾（停插件、断长连接）
    i=0
    while [ $i -lt 10 ] && kill -0 "$pid" 2>/dev/null; do
        sleep 1
        i=$((i + 1))
    done
    if kill -0 "$pid" 2>/dev/null; then
        echo "未在 10 秒内退出，强制结束"
        kill -9 "$pid"
    fi
    rm -f "$PIDFILE"
    echo "wen 已停止"
}

case "$1" in
    start)   start ;;
    stop)    stop ;;
    restart) stop; start ;;
    status)
        if running; then
            echo "wen 运行中（pid $(cat "$PIDFILE")）"
        else
            echo "wen 未运行"
        fi
        ;;
    *)
        echo "用法: $0 {start|stop|restart|status}"
        exit 1
        ;;
esac
```

日志会一直追加到 `wen.log`，久跑记得定期清理或配 logrotate。

### systemd

假设部署在 `/opt/wen`（按实际路径替换）。保存为 `/etc/systemd/system/wen.service`：

```ini
[Unit]
Description=Wen Agent
# 等网络真正可用再启动：QQ/微信长连接、模型接口都要出网
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=wen
Group=wen
WorkingDirectory=/opt/wen
ExecStart=/opt/wen/wen

# 崩溃自动拉起；正常 stop 不算失败
Restart=on-failure
RestartSec=5

# 优雅停止：默认发 SIGTERM，给 15 秒收尾（停插件、断长连接），超时才 SIGKILL
TimeoutStopSec=15

# 需要环境变量时在这里给：
# Environment=WEN_AUTH_PASSWORD=xxxx
# 或放进单独的文件（记得 chmod 600）：
# EnvironmentFile=/opt/wen/wen.env

# 可选加固。别开太狠：exec_command 插件本来就要执行命令、读写工作目录，
# 沙箱开满等于把功能关了。下面这组是不影响功能的底线：
NoNewPrivileges=true
ProtectSystem=full
ReadWritePaths=/opt/wen

[Install]
WantedBy=multi-user.target
```

首次部署：

```sh
# 建专用用户（无登录 shell），并把目录交给它
sudo useradd --system --home /opt/wen --shell /usr/sbin/nologin wen
sudo chown -R wen:wen /opt/wen

sudo systemctl daemon-reload
sudo systemctl enable --now wen
```

日常操作：

```sh
sudo systemctl status wen          # 状态
sudo systemctl restart wen         # 重启
journalctl -u wen -f               # 跟日志
journalctl -u wen --since today    # 看今天的日志
```

两点注意：

- 用了 `User=wen` 之后，终端配置工具要以同一用户、同一目录执行才能连上运行中的实例：`cd /opt/wen && sudo -u wen ./wen config`。
- `config.yaml` 若放在 `/opt/wen` 之外，把那个目录一并加进 `ReadWritePaths`。

## 上下文的组织

一轮请求发出去的上下文分两层：

```
system        [系统环境] + 各插件的固定提示词 + 你配置的系统提示词   ← 整轮之间一字不变
历史          过往消息；隔得久的地方插一行「此处距上一条消息约 14 小时」
<本轮状态>    当前时间、距上一条消息、各插件每轮生成的片段（心情/天气/记忆索引…）
本轮输入      你说的话
```

**当前时间不在 system 里，而在历史之后**。这一条同时解决两个问题：

- **模型对「现在」的判断。** 时间放在 system 开头时离生成位置有几千 token 远，而历史对话里出现过的时刻是叙事事实、就在眼前——聊上十几轮之后，模型会把上次那个时刻当成现在，于是在下午继续演深夜。放到历史之后，并明说「与历史里的说法不一致时以这里为准」，才压得住。同理，历史里隔得久的地方会补一行间隔标记：消息的时间戳本来就存着，只是从不发给模型，于是那十几个小时在上下文里根本不存在。
- **提示词缓存。** 缓存都是前缀精确匹配的，system 里放一个每轮都在变的时间戳，等于让整段 system 加历史永远无法命中。DeepSeek 这类服务端自动缓存的提供商没有任何开关可调，唯一的抓手就是前缀别变。

`/status` 会报出最近一轮的缓存命中量，可以据此确认它确实在生效。

## 编写插件

实现 `internal/plugin` 的 `Plugin` 接口（`Name` / `Description` / `Init` / `SystemPrompt` / `Tools`），在 `cmd/wen/main.go` 的 `buildPlugins` 注册即可。约定：提示词与描述一律中文、只写功能、不含身份信息；`SystemPrompt()` 返回空串表示不注入；插件名限小写字母、数字与下划线（它会被用来拼持久化目录）。

可选接口（不实现则零成本）：

- `Configurable`（`ConfigFields()`）——声明可配置项，设置页据此生成表单并持久化。字段类型有 `int` / `bool` / `string` / `select` / `text`（多行，渲染成 textarea）。
- `CompactObserver`（`OnCompact()`）——在会话历史被摘要替换**之前**收到通知，可借此归档或提炼；返回的注记会追加到摘要末尾，从而只落进该会话的历史。事件广播给所有订阅者（`memory` 与 `session_search` 都订阅了它，各做各的事），返回错误只记日志，不阻断压缩。历史带可见域标签时按标签分组，每组一次事件。
- `ScopeDecider`（`DecideScope()`）与 `TurnPrompter`（`TurnPrompt()`）——见下方「可见域」。
- 操作确认：用 `plugin.ConfirmerFrom(ctx)` 取确认通道，在执行不可逆操作前问一次。第二个返回值为 false 表示当前没有可交互的用户，**不要当作已获同意**；返回 error 同理，拿不到答复不等于得到许可。
- `Dependent`（`Requires()`）——声明必须同时启用的插件。依赖未满足时拒绝启用（开关在界面上置灰），被依赖的插件也无法在依赖方仍启用时关闭。
- `Conflicting`（`Conflicts()`）——声明能力相抵的插件。只告警不阻止。
- `Stoppable`（`Stop()`）——停掉自己起的后台活动。禁用、以新配置重新 `Init`、进程退出三处会调用；只做取消与有界等待，不得等整轮对话跑完。起 goroutine 的插件必须实现它，并保证 `Init` 可重入。
- `TurnObserver`（`OnTurnEnd()`）——观察每轮对话的结束。在收尾的同步路径上广播，实现必须快速返回，耗时工作自行开 goroutine。
- `StatusReporter`（`StatusLines()`）——向状态命令贡献一行运行状况。与 `SystemPrompt` 同契约（廉价、无副作用）。
- `Actionable`（`Actions()` / `StartAction()` / `ActionState()`）——声明可在设置页触发的流程（如扫码绑定），状态含说明文字与一张可选 PNG。`StartAction` 应立即返回，长流程放后台并自带超时。
- `Categorized`（`Category()`）——声明功能分组（基础工具 / 记忆与检索 / 角色演绎 / 后台任务 / 消息通道），设置页据此分节展示。只影响展示，不影响注册顺序。
- `FailureTranslator`（`TranslateFailure()`）——轮次失败时把失败转成一句正常回复的机会（`roleplay` 据此把内容拦截演成角色的走神）。单所有者、按逆注册序征询，只在真人在场的轮次尝试；转译文本以正常助手消息落盘，原始错误转入会话注记；配置类错误（`llm.IsConfigError`）必须放行原样报出。
- `NoticeObserver`（`OnNotice()`）——会话注记落盘并送达 Web 界面之后收到广播（IM 通道据此把后台工作的说明推给绑定用户）。事件携带的是已截断的落盘文本。

插件之间还有两样共享的基础设施，核心不知道它们：`internal/imbot`（消息通道骨架，见下）与 `internal/cue`（「开口理由」公告板——产生方按**事件**投递而不是按状态投递，同 (Source, Key) 幂等覆盖，必须带过期时刻；心跳开口前取走全部未过期的理由。只存内存，检测状态的权威在产生方自己的持久化里）。

`InitContext` 提供这些运行环境：`Workdir`（工作目录）、`StateDir`（该插件专属的持久化目录 `<配置目录>/plugins/<插件名>/`，可能不存在需自行创建）、`Sessions`（会话的只读窄查询：最近活跃的会话、某会话是否还在）、`SessionDir`（会话目录，只给需要读会话正文的检索与归档类插件）、`Complete`（用当前模型做一次一问一答的辅助调用，不带工具、不写会话）、`RunTurn` / `NewSession` / `Compact`（以插件身份跑一轮完整对话、新建会话、压缩历史）、`Status`（模型配置与会话用量快照）、`Notice`（往会话里留一行只给人看的说明）。除 `Workdir` 外为空/nil 均表示当前不可用，插件应据此拒绝启用或降级，不要退化到写进程当前目录。`Complete` 与 `RunTurn` 每次调用都产生真实的模型开销，只放在低频路径上。

`RunTurn` 与 `Notice` 由 Manager 包一层自动注入发起方标记，插件无法伪装成前台；`RunTurn` 在会话忙时立即返回 `ErrSessionBusy` 而不排队——后台任务堆在锁上，只会在解锁瞬间连环轰炸同一个会话。`Notice` 写出的内容落盘、在界面实时展示，但永不进入模型上下文，也不进压缩摘要：后台工作在轮次收尾之后才跑完，那时事件流已经关闭，结果否则只能进日志。

再写一条消息通道的话，通道无关的部分（入站分发与去重、命令集、按用户串行、会话绑定、确认代理、通道路由）在 `internal/imbot` 里，插件只需实现 `imbot.Sender`（把一段文本发给某个用户）并把入站消息归一化成 `imbot.Message`。

### 可见域

同一会话内的消息可以分区，使一部分内容对某些轮次不可见。标签的语义完全由插件定义，核心只做三件事：给消息打标签、按标签过滤历史、按标签分组压缩——它不知道「人格」这回事。**空标签始终对所有域可见**，因此升级前无标签的历史继续可用，「共享」也不需要任何插件参与就成立。

两阶段：`ScopeDecider.DecideScope` 先定域（单所有者机制，按注册顺序第一个返回非零 `Scope` 的插件胜出），`TurnPrompter.TurnPrompt` 再按已定的域注入一次性提示词。之所以分开，是因为 `memory` 要按可读域过滤记忆索引，而域由别的插件裁决，单阶段广播里两者无序。可见域随后经 `context` 传给工具执行，用 `plugin.ScopeFrom(ctx)` 取。

`SystemPrompt()` 的签名不变：它的契约是廉价、无副作用、随时可调（插件列表接口会对**禁用**的插件也调用它），需要会话上下文的内容一律走 `TurnPrompt`。

要把数据按可见域分开存放，用 `plugin.DomainDir` 与 `plugin.ReadDomains`：空标签用基准目录本身，其余域用同级的 `<base>-<tag>`。标签会被拼进目录，故按插件名的字符集校验，不合规的裁决整条作废。

可见域还能绑通道：插件安装 `imbot.SetRouter` 之后，各通道就按「这个会话的回复该发往哪条通道」投递，与这一轮从哪条通道进来无关（`dual_persona` 用它让表里两面各占一条 IM）。这部分在 `internal/imbot` 里，核心不参与，`imbot` 也只认通道名。

**可见域是上下文隔离，不是沙箱**——任何提供通用文件或命令通道的插件都能绕过它。
