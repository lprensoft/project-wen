## Heartbeat (heartbeat plugin)

Lets the character speak first. On an interval it wakes the model and runs a full turn on the **most recently active session** (with the system prompt and every enabled plugin's prompt), and the output goes straight into that session. Off by default — something that burns quota unattended should be turned on deliberately rather than starting to spend money the moment it is installed.

- **A heartbeat does not count as activity**: only sessions a human has interacted with (through the web UI or a chat channel) are candidates, or the heartbeat would keep recognizing itself as active and renew its own lease forever.
- **It does not interrupt**: the countdown restarts from the moment you finish speaking. The heartbeat is a mechanism for speaking up when nobody is talking; cutting into a conversation both interrupts it and makes the interval setting meaningless.
- **The character sets its own pace** (on by default): the model has a `set_heartbeat_interval` tool, so it moves the next opening closer when the conversation is lively and pushes it back when you say you are busy, with the countdown recomputed from that moment. It is called in passing during a conversation, so it costs no extra model call, and the reason is written down with the call and lands in the log. The current pace is shown to the model each turn — without seeing where things stand, "the conversation is lively, speed up" can never trigger.
- **It can actually sleep**: `pause_heartbeat` suspends speaking up for a while (at most a day; a night's sleep is reported as seven to nine hours), after which the normal pace resumes — and a word from you resumes it immediately. Idle decay does not count during a pause: that quiet was the character's own decision, not evidence that nobody wants to talk. The first beat after a pause ends counts as waking up, and the pace returns to the base value.
- **Both slower and faster have automatic paths**: while nobody is talking, idle decay slows the interval by one step (×1.5) every 15 minutes up to the maximum, without waiting for the model to think of it; and when a human turns up, a pace slower than the base value is mechanically restored to it (the slowness accumulated by decay, and stale arrangements like "she is busy today", are void on the spot), while a pace faster than the base value is kept — a pace sped up mid-conversation is not knocked back by one new message. Neither costs a model call. The interval is always rounded to the minute and clamped to the bounds you set.
- **It speaks when there is something to say, not because the timer went off**: the heartbeat is also the consumer of the "reason to speak" board. When another plugin posts something worth mentioning (rain has just started, tomorrow's forecast has rain in it), the next beat is brought forward to the minimum interval and the reason is handed to the model with the heartbeat prompt — whether and how to say it is still the model's call. A pause outranks everything: you do not wake a sleeping person for a shower. If the turn fails, the reason goes back on the board for the next beat, and expired ones are dropped ("it has just started raining" is wrong two hours later). The board is memory-only: a restart loses only the sentence that had not been said yet, and any reason that still holds will be rediscovered by the producer's next check.
- **A prompt per context**: one heartbeat template says the same thing every time it wakes up, and that is exactly where the mechanical feeling comes from. You can configure several by context (`[before bed]`, `[small talk]`, `[working]`…), and the model declares the current context in passing when it adjusts the pace or pauses, so the next heartbeat uses that one — "pause until morning at bedtime, and open with a good-morning when it wakes" becomes a single action. A "life" context ships as an example: live the time first (update the scene, the mood and the rest, in proportion to how much time actually passed), then decide whether to speak at all, and stay quiet with nothing to say — a character should not be frozen between two conversations. Edit or delete it as you like; once cleared it does not grow back.
- **After a long gap, review before speaking**: a wake-up more than 12 hours after the last conversation (longer for someone whose heartbeat is slow anyway) carries an extra instruction — review the saved memories and recent experience first, then decide whether and what to say, rather than picking up the thread of a long-stale conversation. Picking it up just reads as not being properly awake.
- **Turning dynamic heartbeat off** gives a fixed interval that the model cannot change either: calling those two tools is refused, with a note about where to turn it on.
- **The prompt is a one-shot input**: a heartbeat prompt is sent to the model only on its own turn. It does not enter later context, does not enter compaction summaries, does not affect the session title, and is rendered in the UI as a one-line source note rather than a user bubble. The assistant's reply is kept as usual. How long it has been since the last conversation is appended automatically.
- **Status line**: the heartbeat line in `/status` reports the current pace, the context and the next occasion, or the resume time while paused.

| Setting | Default | Description |
|---|---|---|
| `interval_minutes` | 30 | The base interval; with dynamic pacing off, this is the fixed interval |
| `prompt` | built-in | The heartbeat prompt (multi-line); it can say anything you like |
| `dynamic` | on | Lets the model choose when to speak next or pause for a while, and slows the pace gradually while nobody is talking; off means a fixed base interval |
| `context_prompts` | the built-in "life" example | Per-context prompts (multi-line): a line of its own reading "[context name]", followed by the lines belonging to that context, in as many blocks as you like; saying "default" switches back to the prompt above. Cleared, the prompt above is always used |
| `min_minutes` / `max_minutes` | 5 / 120 | The bounds on dynamic adjustment; a value outside the range is clamped and the model is told so |

## Scheduled tasks (scheduler plugin)

The model can create scheduled tasks during a conversation (one-off / recurring / daily). When the time comes, a turn runs in the background and its result is written into the most recently active session — the same rule the heartbeat uses. On by default.

- **Tasks do not run inside the scheduling loop**: each due task gets its own goroutine with a recover and a 15-minute timeout, so one task hanging or crashing affects neither the program nor the others.
- **When the session is busy**: a one-off task retries by the minute, at most 5 times; a recurring task simply skips and waits for the next cycle — background tasks piling up on a lock only produce a barrage the instant it is released.
- **Missed while the process was down**: a one-off task is run late if it is within 24 hours, and otherwise marked expired rather than suddenly doing something that stopped mattering long ago. Completed tasks are kept for 24 hours so `list_tasks` can still show them.
- **Runaway protection**: at most 200 tasks; past that, creating one is refused.
- **Noting future things in passing**: the prompt steers the model toward creating a one-off task when the other person mentions something in the future (a Friday interview, a trip next week) so it can bring it up when the time comes — expressed in passing with a tool, at no extra cost.
- **Tools**: `schedule_task`, `list_tasks`, `cancel_task`.
