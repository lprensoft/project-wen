# 角色的生活

[← 插件总览](README.md)　·　[← 返回 README](../../README.md)

## 场景感知（scene 插件）

角色要有连续的处境，光有性格不够——上一次在哪、那间屋子什么样，模型从对话历史里看不出来，压缩一次更是全没了。本插件把**舞台设定**（用户配置的固定环境）与**场景记忆**（对话中出现过的地点）分开：前者每轮全额注入，后者按可见域从库里取。默认不启用，硬依赖 `roleplay`——没有角色，舞台没有站的人。

- **两段注入**：`[场景与环境设定]` 是你写死的舞台，只读不改；`[场景感知]` 是记录判据，要求把对话里出现的城市、街区、建筑、房间、店铺或反复出现的活动场所记下来，并明确「只记场景本身——位置、与其它地点的关系、布局、陈设、氛围，不记一次性的动作与对话」。
- **先查再记**：判据里要求记录前先看 `[场景记忆]` 里有没有同一地点，已有且一致就不再记，有补充或变化用 `replace` 更新原条目而不是另建一条。否则同一间屋子会攒出好几份互相矛盾的描述。
- **工具**：`save_scene`、`list_scenes`、`delete_scene`。库存在 `<配置目录>/plugins/scene/scenes/`，启用可见域隔离后带标签的库落在同级的 `scenes-<标签>/`。
- **注入有上限**：场景记忆随每轮对话重复发送，超出字节上限时先省略描述只留名称，仍超出才截断——与记忆索引同一套降级思路，优先保住「有这个地方」这件事。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `stage` | 空 | 场景与环境设定（多行）。留空则只保留记录能力，不注入固定舞台 |
| `max_scenes` | 30 | 注入的场景条数上限，超出按最近更新保留 |
| `max_inject_bytes` | 8192 | 场景记忆的注入字节上限 |

## 天气感知（weather 插件）

外面在下雨还是刚放晴，是一条持续起作用的背景——它不构成话题，但影响环境的样子、人的状态和关心的方向。本插件按设定的城市定时取现实天气（数据源 [Open-Meteo](https://open-meteo.com/)，免费、无需密钥），把此刻的天气每轮注入。默认不启用，硬依赖 `roleplay`。

它注入的是**环境状态**而不是一个可调用的工具，这也是它归在「角色演绎」而不是「基础工具」的原因：通用对话里每轮塞一行天气只是噪声，真要问天气，模型自己用 `fetch_url` 抓就够了。

- **天气首先得是角色自己的**。只给「你所在地的天气」时，那是一条关于第三方的信息——角色对它既没有体感也没有可做的反应，于是在对话里几乎不起作用。所以这里分角色与用户两处地点，同城时合成一处，代入感最强。
- **两种天气有两种用法**，注入的准则分开写：**自己那边的天气进入环境与状态**——光线、声音、冷热、开不开窗、出门方不方便，写进场景与动作的描写里，被感觉到而不是被谈论（不需要说「今天下雨」，写雨声、写潮气就够了），也自然地影响语气与精神头；**对方那边的天气是一件你知道的事**，用于关心的方向，不当开场白。
- **带上昨天、今天与明天**：同一次请求顺带取回三天的概要（零额外调用），接在现况之后注入。做注入而不是工具，是因为真人不「查」天气——早上瞟过一眼今天的预报，出门带不带伞按它来；昨天则是记得。这两样全天都在。**明天的概要只在该看的时候出现**：默认从傍晚六点起（`tomorrow_from_hour`，0 = 全天），白天的人想的是今天，临睡前、计划明天的事时才去看明天；白天只有你提到「明天」时它才看一眼。明天的预报第一次出现在角色眼前的时刻会记下来，三小时后标「（早些时候就知道了）」——预报每轮都在眼前，不标的话模型会把几小时前就看过的「明天有雨」当成新消息，一遍遍提醒带伞；准则里也写明预报是背景常识，提醒说一次就够。按日期核对而不是信字段名：跨过午夜后缓存里的「明天」其实是今天，对不上的那天不注入。
- **天气是开口的理由**：每次刷新后对比前后两次观测，现况里降水的开始或停止、明天的预报里出现降水，都会投递一条开口理由（见[心跳](background.md)），由心跳带进主动开口的轮次——「刚下起雨了」「明天有雨，记得带伞」比任何无话找话都像真人。只报转变不报状态，状态本来就每轮注入；前一次观测断档太久（宕机横跨）不报，「刚下起来」就成了错话。明天有雨的理由同样只在「看明天」的时段里投、一天只投一次（刷新不重投），雨从预报里消失时撤回还没说出口的那句。
- **同城只查一次**：开着「与我在同一个城市」时只按角色的城市取数。两处填了同一个地名也会自动合并——否则会注入两行一模一样的天气。
- **不填城市就什么都不注入**，包括那段讲天气怎么用的规则。虚构或历史舞台就该是这个状态：留空，或干脆关掉插件。
- **舞台优先**：`[场景与环境]` 设定的舞台不是这里给出的地方时，以舞台为准，天气不参与场景描写。
- **后台刷新，注入只读缓存**：`TurnPrompt` 在每轮对话的同步路径上，在那里发网络请求就是让每一轮都替一次超时买单。
- **过期就不注入**：取不到新数据时，让角色不知道天气，好过把三小时前的天气当成此刻。因此过期时限不得小于刷新间隔——否则刚取到的也立刻算过期，等于永远不注入。一边取到一边取不到时，注入取到的那一边。未收录的天气代码回落到「天气不明」，注入的内容宁可含糊也不能是错的。
- **测试按钮**：设置页齿轮里有「测试这些城市」，读的是**还没保存**的输入，把每一处解析成了哪个地方、当时的天气是什么都列出来；一处失败也会把另一处的结论一并给出。
- **状态行**把「没配城市」「取不到」「过期了」分开报，过期标在具体那一处上——两处地点时，一处失效不代表另一处也没在用。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `persona_location` | 空 | 角色所在的城市。主要的那一个，角色自己那边的天气才会进入它的环境与状态 |
| `same_city` | 开 | 与我在同一个城市。开启时只查上面那个城市，下面一项不生效 |
| `user_location` | 空 | 我所在的城市，作为角色知道的一件事。仅在上一项关闭时生效 |
| `refresh_minutes` | 30 | 后台刷新间隔（分钟），最快 10 分钟 |
| `stale_minutes` | 60 | 距上次成功取得超过这么久就不再注入，不得小于刷新间隔 |
| `tomorrow_from_hour` | 18 | 几点起看明天的天气：此前只有你提到「明天」时才看一眼；0 表示全天都看 |

## 持有物（belongings 插件）

冰箱里有什么、衣柜里有几件外套，模型从对话历史里只能翻到只言片语，压缩一次就全没了，于是上周买的菜这周还在，昨天说吃完的鸡蛋今天又能炒。本插件把持有物记成按容器分的清单（冰箱、衣柜、书架……每类一个容器），每轮注入，演绎与它保持一致：做菜只用冰箱里有的食材，穿衣只从衣柜里挑，清单里没有而剧情需要的东西先经历取得再使用。默认不启用，硬依赖 `roleplay`。

- **只记「现在有什么」**：穿上脱下、拿起放下不改清单；物品的来历与意义（谁送的、为什么买）值得长期记住时另存为记忆。可数的物品带数量（鸡蛋×6），消耗时报减少的数量，减到 0 自动移除。
- **物品会变旧**：每件物品带放入时间，隔久了的标着「N 天前放入」，食材该不该扔由模型在演绎里自然处理并同步更新清单。
- **工具**：`update_items`（add 放入 / remove 取出或消耗，同一容器的变化合并成一次调用，容器不存在时自动新建）、`list_items`（可按容器或关键词过滤）。按可见域分库存放。
- **有上限**：容器数与单容器物品数都有限，超出拒绝放入并提示先清理——清单不该长成仓库账。注入同样有字节上限，超出先省略物品只报件数，仍超出只注明容器数。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_containers` | 10 | 容器数量上限 |
| `max_items` | 50 | 单个容器的物品上限 |
| `max_inject_bytes` | 4096 | 清单的注入字节上限 |

## 人物（people 插件）

角色的闺蜜叫什么、妈妈住哪、楼下咖啡店老板认不认识她，模型没有地方记，于是每次临场编一个，名字三天换一次。本插件给角色一份人物库：每个人有名字、关系、几句设定、亲近度（点头之交 / 认识 / 熟 / 亲近）与上次来往的时间和一句摘要，每轮注入一行一人的清单，演绎里提到的熟人只从这里来，新认识的人先登记才算存在。它存在的理由是约束而不是记录——有了落盘的名册，社交圈才不会随对话漂移，之后的日程插件排「和谁」时也只认这里的名字。默认不启用，硬依赖 `roleplay`。

- **只记「这个人是谁、走得多近」**：与某人之间发生过的具体事值得长期记住时另存为记忆；上次来往只留一句摘要。对方本人不进人物库——那由角色扮演的「我的信息」与记忆负责。
- **工具**：`upsert_person`（登记或更新，只传要改的字段；有过一次来往时传 `met_now` 记下时刻与一句摘要）、`list_people`（全量，可按关键词过滤）、`remove_person`（搬走、断联，要写缘由）。按可见域分库存放，已有的人写回他所在的域。
- **有上限**：人数有限，超出拒绝登记并提示先移除不再往来的人。注入同样有字节上限，超出先只留名字与亲近度，仍超出只注明人数——名字在，模型才知道这个人存在。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_people` | 30 | 人数上限 |
| `max_inject_bytes` | 2048 | 清单的注入字节上限 |

## 日程感知（agenda 插件）

角色在对话之外也该有自己的一天，但模型没有地方记「今天几点要去做什么」，于是每次被问起都临场编一段行程，上一轮说在图书馆、下一轮就在海边。本插件让角色每天醒来给自己排一张两到四件事的表（留大段空白，一天不必塞满），到点自动跑一轮让它决定去不去、回来再跑一轮写下一句经历，遇到变故会改、会挪、会跟你商量；定在某天某时的事单独登记为约定，到那天排进表里。表里的「和谁」只认人物库里的名字。答应下来但没有具体时刻的事（明天给你带两个菜、周末把书还回去）另记一份台账，兑现或没做成都要了结。默认不启用，硬依赖 `roleplay` 与 `people`。

- **规划时机**：新的一天（默认凌晨五点起算，之前的时段归前一天）第一轮对话或心跳结束后，在同一个会话上起一轮【规划今天】；没人说话、心跳也关着的日子不排——没人看得到的表排了也白排。两次没排成就留一条会话注记，到明天再说。
- **开始与结束**：到了表上的时间，在最近活跃的会话上跑一轮开始轮次（晚了会注明晚了多久，整项都过去了就只补记一句），结束时再跑一轮写经历、顺手更新现场、人物与心情。没有任何会话时不新建。派发记录随表落盘，重启不重发；刚启动的两分钟内不派发。
- **与你的约定动不得**：标了「与对方一起」的项一律不能挪、不能取消、不能延期，工具层直接拒绝并告诉角色要先商量；你在对话里明确同意后它才能改。约定开始前一小时会给心跳投一条开口理由，活动结束回来时也投一条，说不说由心跳那一轮的模型定。
- **忙不忙写在公告板上**：活动进行中把「在忙什么、忙到几点、能不能回消息」写进 `internal/availability`，供心跳与消息通道读取（本期只写不读）。与你在一起的活动不写——正和你在一起，不存在不回你消息。
- **答应过的事**：随口答应的一句话此前无处可去——不是记忆（定在某天的单次安排按约定归日程）、不是约定（没有时刻）、也不是当天表上的项，于是只以对话文本的形式活着，而对话文本既没有时间锚也没有完成状态。现在它记成一份带到期日与兑现状态的台账，两个方向都记（角色答应你的、你答应角色的），在注入里字面上分得开。了结之后立刻停止注入，这正是「已经带过的菜第二天又被提起一遍」要防的事；到期日过后给一天宽限（你可能晚上才兑现），再没了结就自动记为「没做成」并留一条会话注记，也停止注入——一条永远挂着的待办，就是换了个载体的同一种病。
- **工具**：`set_day_plan`（只在规划轮次用，整表覆盖，今天的约定缺一条即拒绝）、`update_day_plan`（开始、做完、挪时间、延期、跳过、取消）、`add_commitment`（登记约定；传今天的日期时直接加进今天的表）、`cancel_commitment`、`list_commitments`、`add_promise`（记下答应的事，写清哪天兑现、谁答应的）、`settle_promise`（做到了 / 没做成 / 不作数了）、`list_promises`（回头查，含已了结的）。按可见域分表，不跨域合并——两条故事线各有各的一天。
- **注入**：`[今日安排]` 由代码算好结论（此刻在做什么、已进行多久、下一项还有多久、今天已做了什么），`[未来约定]` 按日期最近优先，`[答应过的事]` 只列还没了结的、每轮最多六条（超出报「另有 N 条」）。有字节上限，超出先去掉已做项的经历，再压成条数，最后约定只剩条数；进行中与下一项永远保留。表尚未排定时注入「尚未排定」，角色不会凭空宣布行程。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `auto_plan` | 开 | 每天自动规划；关掉只维护约定与手工改的表 |
| `run_activities` | 开 | 到点自动跑开始 / 结束轮次；关掉只注入表 |
| `day_start_hour` | 5 | 几点算新的一天 |
| `max_items` | 4 | 一天最多几项（硬上限 6） |
| `start_grace_minutes` | 15 | 到点多久内算准时 |
| `remind_before_minutes` | 60 | 与你的约定提前多久投一条开口理由，0 关 |
| `max_commitments_inject` | 8 | 每轮注入的约定条数 |
| `max_inject_bytes` | 2048 | 两块注入合计的字节上限 |

## 人际感知（relationship 插件）

性格稳定有一半是「对这个人的态度稳定」。此前角色对你的态度每轮都从接触记录与记忆索引里重新推一遍，于是忽远忽近——上一轮还腻着，这一轮就客气生分。本插件把「我们之间」记成一份小快照：处在什么阶段（「刚认识」「暧昧中」「热恋」「冷战中」，自由短语不做枚举）、彼此怎么称呼、最近一次关系上的变动（和好、吵架、表白、冷落，注入时带「N 天前」）、相处出来的默契与禁区（「她不爱被催」「晚安一定要说」，最多五条）、对方的一句近况，作为 `[关系]` 块每轮注入，态度与分寸照它来。没有配置项。默认不启用，硬依赖 `roleplay`。

- **只在关系真的变了时更新**：表白了、吵了、和好了、称呼变了、定下了新的默契或禁区。寻常一轮对话不改关系。`update_relationship` 只传变化的字段，空串清除该项，`bonds` 整体覆盖、传空数组清空。各字段都有长度上限，超出报错让模型压缩后重试而不是截断——一条被截掉一半的禁区，意思可能正好反过来。
- **过期的「最近」不是最近**：超过 30 天没动的最近变动不再注入，其余字段照旧。
- **只记「我们之间」**：对方是谁、喜欢什么、经历过什么这类事实仍归角色扮演的「我的信息」与记忆，近况只留一句当下的、用来拿捏分寸。禁区也只写已经硬下来、以后一直不碰的那几条——位置只有五个，一次明确表达过的不愿意归长期记忆的 `边界` 类：这里记的是现在不碰什么，那里记的是当时为什么划下这条线。按可见域各存一份，不跨域合并——关系属于人格，表人格与对方是老友、里人格与对方是恋人，两份各自成立。
- **一键重置**：设置页齿轮里有「重置关系状态」，含各人格分开保存的那几份。不可撤销。

## 心里话（unspoken 插件）

活人有「没说出口的事」：嘴上说没事，心里记着，这口气能记三天。模型没有地方放这口气，于是下一轮就真的没事了。本插件给角色一份有上限的清单：对你的真实看法、憋着的话、在等的事、决定暂时不提的事，一行一条带「N 天前」作为 `[心里话]` 块每轮注入。判据要求它们**不直接念出来、不写进`【】`**，但决定态度、语气与潜台词。默认不启用，硬依赖 `roleplay`。

- **只记会在心里留几天的事**：`keep_unspoken` 记一条，不是每轮都记；心情的起因值得记住时也记一条——心情会回落，起因会丢，这里能留住「为什么不高兴」。说出口了、想通了、不再在意了，用 `let_go` 放下，按序号或原文片段定位，片段命中多条时报错并列出候选。
- **有上限**：条数满了自动放下最早的一条并在回执里说明。注入同样有字节上限，超出只保留最近的几条并注明另有几条——模型知道心里还压着事，不会演成什么都没发生。
- **只记「我心里」**，不记对方的事实——那归角色扮演的「我的信息」与记忆。按可见域各存一份，里人格憋着的话不会成为表人格的潜台词。
- **一键清空**：设置页齿轮里有「清空心里话」，含各人格分开保存的那几份。不可撤销。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_entries` | 8 | 条数上限（1-20），满了自动放下最早的一条 |
| `max_inject_bytes` | 1024 | 清单的注入字节上限 |

## 身体感知（body_sense 插件）

同一处接触在第一次和第二十次不该是同样的反应，但模型没有跨会话的计数，于是每次都从零开始演。本插件按部位记累计次数，划成熟悉阶段，把状态与「不同阶段该是什么取向」的准则一起注入。**插件只提供机制与状态，不写台词**——具体怎么演由角色设定决定。默认不启用，硬依赖 `roleplay`：没有角色，身体就没有归属。

- **两个正交的维度**：熟悉度（累计次数 → 初次 / 生疏 / 适应 / 熟悉 / 习以为常）与私密度（日常 / 亲近 / 亲密 / 私密四档）。私密度不参与熟悉度计算，只随状态注入——它决定「起点多强烈」与「衰减到什么程度为止」，熟悉度决定「衰减了多少」。合成一个阈值等于用一个维度表达两件事，两边都表达不好。
- **部位表可改**：四档各一个多行文本框，一行一个部位。内置的默认表按「在什么关系阶段才会自然发生」分档而不是按解剖学：「手」与「手指 / 手背 / 手腕」分开（牵手、碰指尖、握手腕是三种强度），「腰」放在亲密档（中文语境里搭腰是明确的亲密动作），不分左右（分了计数摊薄一半而叙事上从不区分），私密档只留三条（条目越多模型越倾向往这一档上报，而这一档误报的代价最高）。
- **即时身体状态**：唤起与疲劳各 0-100，补的是接触计数（长期熟悉度）与心情之间缺的那层——「此刻身体是什么状态」。由模型按演绎报变化量（`adjust_body_state`，一轮最多一次，两项可同时报），随时间各按各的速度向 0 回落，回落的过程本身就是余韵与恢复，不单设状态。落盘在会话之外，跨会话天然接力。按可见域各存一份，读取时对可读域逐字段取最大值——不学心情的「各域完全独立」：心情属于人格，身体是同一具。
- **工具**：`record_touch`（记下接触并回显累计次数与阶段，判据要求「先记录、拿到回显、再写这一处的反应」）、`list_body_state`、`adjust_body_state`。
- **一键重置**：设置页齿轮里有「清空接触记录」与「重置身体状态」，都含各人格分开保存的那几份。不可撤销。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `parts_daily` / `parts_close` / `parts_intimate` / `parts_private` | 内置表 | 四档部位表（多行，一行一个）。部位名随工具声明每轮发送，超量报错而不截断——被截掉的部位模型看不见，你却以为配上了 |
| `familiarity_pace` | 中 | 阶段推进的快慢：慢（次数减半）/ 中 / 快（次数加倍）。中档下 1 次为初次、2-3 生疏、4-9 适应、10-19 熟悉、20 以上习以为常 |
| `arousal_decay_per_hour` | 30 | 唤起每小时向 0 回落的点数，0 = 不回落 |
| `fatigue_decay_per_hour` | 10 | 疲劳每小时向 0 回落的点数，0 = 不回落 |
| `state_max_delta_per_call` | 30 | 单次调整唤起或疲劳的上限，超出按上限收并告知模型 |
| `max_inject_bytes` | 2048 | 接触记录的注入字节上限；超出时先省略次数只留阶段，再按阶段归并 |

## 心情（mood 插件）

角色的状态应当被互动改变，也应当自己平复。心情值范围 -100 到 +100，0 为平静，由模型在被夸、被冷落、玩笑开过头、久别重逢这类事发生时主动上报变化量，并随时间向平静回落。默认不启用，硬依赖 `roleplay`。

- **先调整、再演绎**：判据里这一条不能省。心情注入发生在轮次开始，工具回显要到模型写完话才到达；不先调工具的话，被说了重话的那一轮仍然按上一轮的好心情在回应，情绪要迟一拍才落下来。
- **报变化量而不是目标值**：好一点是 +10，很难过是 -35。一轮最多调一次，把这一轮的事合起来算。
- **心情只改表达，不改角色**：注入的准则明确心情影响的是话多话少、主动被动、动作松紧，而不是角色是谁、也不是事实与立场；并要求不要把心情当结论说出来（不出现「我现在心情是 -30」这类话，也不报数值）。
- **随时间回落**：按每小时若干点向 0 靠拢，因此不需要为「过了一阵子该好些了」专门调整。填 0 表示不回落，心情会一直停在上次的值。
- **工具**：`adjust_mood`（报出变化量，回显调整后的心情）。
- **一键重置**：设置页齿轮里有「重置为平静」，含各人格分开保存的那几份。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `decay_per_hour` | 5 | 每小时向平静回落的点数，0 = 不回落 |
| `max_delta_per_call` | 30 | 单次调整的绝对值上限。改小让情绪变化平缓，避免一句话就从开心跌到谷底 |

## 健康感知（health 插件）

真人会偶尔着凉、头疼、吃坏肚子，角色却永远健康——不是因为设定，而是没有地方记。本插件给角色一份身体状况：会不会生病、生什么、多重、大概几天、怎么处理，全由模型在事发的那一轮按剧情判断并记下；之后严重度随时间按病程曲线自动起、峰、落，恢复快慢由处理方式决定（硬扛慢、吃药中、就医快），读取时按落盘时刻折算。原则是**代码管时间，模型管判断**：不做疾病模拟器，没有随机事件，也没有 HP 条——每轮注入的是处境（「感冒第 2 天，从难受转成有点不舒服（吃了药），预计再两三天好」），不是数值。默认不启用，硬依赖 `roleplay`。

- **发作可以延迟**：下午淋的雨晚上才头疼。模型当场记下「几小时后发作」，到点由代码投一条开口理由，心跳会提前一拍让角色自己说「开始头疼了」；提前痊愈则撤回还没说出口的那句。
- **有硬约束**：痊愈后一段时间内不再登记新状况、同时记着的有上限、严重度封顶在你选的那一档——防的是模型贪戏剧性。拒绝时把规则告诉模型，它才不会换个名字再试。
- **刚病好会有余波**：冷却期内注入「还有点虚」，冷却期后同样长的一段注入「最近容易着凉」，易感只基于插件自己知道的事（刚痊愈）；天气、疲劳这类诱因由模型自己从上下文判断。
- **只演绎日常小恙**：判据划了红线——不演绎需要急救或住院的病情，不拿生病制造戏剧。对心情与疲劳的影响不在代码里耦合，判据要求模型登记时顺手用 `adjust_mood` / `adjust_body_state` 表达。病着时话少、没精神的表现指引随状态块附一句，不做新机制。
- **工具**：`set_condition`（记下状况名、最重时的档位、几小时后发作、病程天数、处理方式）、`update_condition`（换处理方式、改严重度、标记痊愈）。按可见域各存一份。
- **状态行与一键清除**：有状况时 `/status` 多一行「🤒 身体：……」；设置页齿轮里有「清除全部身体状况」，连痊愈记录一起清、冷却随之解除，含各人格分开保存的那几份。不可撤销。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `cooldown_days` | 7 | 痊愈后多少天内不再登记新状况（1-60） |
| `max_conditions` | 2 | 同时最多记几个状况（1-3） |
| `max_severity` | 难受 | 严重度上限：有点不舒服 / 难受 / 病倒了。模型报得更重时按这一档收并告知 |

## 现场状态（presence 插件）

场景与姿态此前只能靠模型翻历史里最近一处`【】`演绎来延续，历史一压缩、会话一换，现场就断了，于是穿着越聊越漂移、明明在厨房下一句坐在了床边。本插件把角色此刻的**现场**记成一份快照——所在地点、穿着、姿态与相对位置、正在做的事、持续生效的状态（「只开了床头灯；窗开着一条缝」）、当前感官焦点——作为 `[当下状态]` 排在本轮状态块的**最后**、离生成位置最近，演绎从那里继续。没有配置项。默认不启用，硬依赖 `roleplay`。

- **只传变化的字段**：`update_presence` 非空值覆盖该项、空串清除该项、没提到的保持原样；现场变化时（换了地方、脱了外套、灯灭了）随手更新，一轮至多一次。
- **隔久了的字段会标时间**：超过半小时没动的字段标着「N 前记下」，给模型一个判断「这项是否已自然失效」的线索（睡了一觉，昨晚的姿势就不作数了），又不让每行都挂着时间戳。
- **只记可观察的现场事实**，不写情绪与心理活动——那是 `mood` 的事。按可见域各存一份。
- **一键清空**：设置页齿轮里有「清空现场状态」，含各人格分开保存的那几份。不可撤销。

## 文风观察（style_watch 插件）

角色有没有漂，此前只能凭感觉——没有任何手段知道「作为 AI」「希望这对你有帮助」这类回归标记出现过几次，也没有回复长度与【】占比的长期曲线，每次调提示词都是盲调。本插件把这件事变成数字：每轮对话结束后用一组纯正则规则（`internal/stylecheck`，零模型调用）检查助手的最终文本，按天累计命中、字数与演绎占比。**只测量、只记录，不改写回复、不重试、不把结果告诉模型**——先有数字，再谈要不要干预。默认不启用，硬依赖 `roleplay`（检测的是角色扮演里的助手腔，写代码时用列表与加粗是对的）。

- **规则对应 `roleplay` 的 [自然表达]**：自称 AI / 语言模型 / 助手、客套开场（「好的，」「当然！」）与谄媚开场、客套收尾（「希望这对你有帮助」「还有什么想聊的」）、过渡套话、「首先…其次…」编号、「不是…而是…」、过度对冲、泛指权威、伪分析、宣传腔、填充语、三段式总结、markdown 标题 / 列表 / 加粗、emoji。每条有稳定的 id（如 `closing_cliche`）与中文标签；【】里的演绎只豁免「少用修饰」类规则。命中是启发式的，看趋势，不当判决。
- **按天统计，真人与后台分开计**：心跳、定时任务的轮次另记一列，不冲淡真人对话的数字。保留最近 30 天，落在 `plugins/style_watch/stats.json`，重启不归零。
- **状态行**：`/status` 里一行「✍️ 文风：今日 42 轮，助手腔 3 次（客套收尾 2、加粗 1），均长 58 字，演绎占 23%」，没数据时报「今日尚无数据」。
- **会话注记**：命中时在当前会话留一行「✍️ 文风提醒：客套收尾「希望这对你有帮助」」，一轮多处合并成一条。只给人看，不进模型上下文；可关。
- **工具**：`style_report`（最近 7 天每天一行）。设置页齿轮里有「查看 30 天报告」与「清空统计」（换角色或改完提示词后用）。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `notify` | 开 | 命中时写会话注记 |
| `ignore_rules` | 空 | 一行一个规则 id，被忽略的规则不计不报；拼错的 id 保存时会被拒绝并列出可用的 |
