## 远程使用（qq_bot / wechat_bot / feishu_bot / lark_bot / telegram_bot 插件）

五条通道，都把一个远端用户映射成一个普通会话——远程会话就是普通会话，Web UI 刷新即可看到，两边聊的是同一份历史。默认都不启用。

通道无关的部分（入站分发与去重、命令集、按用户串行、会话绑定、确认代理、推送）只有一份实现，各插件只负责自己的协议层，所以下面这些约定在五条通道上完全一致：

- **命令集**：`/new` 开新会话、`/status` 看模型与用量、`/compact` 手动压缩、`/help`，以及危险操作确认的 `/apply` / `/deny`。
- **白名单之外一律拒绝**，只记日志。白名单为空时拒绝所有人；陌生用户的 id 会写进日志，方便你抄进白名单。
- **危险操作可远程确认**：`exec_command` 需要确认时，请求推到远端，等 `/apply` 或 `/deny`；超时按拒绝处理。拿不到答复不等于得到许可。
- **后台轮次会推送**：心跳、定时任务这类后台轮次落在绑定的会话上时，助手的最终文本会主动推给远端——否则结果只进会话文件，你在手机上永远看不到。前台轮次、自己发起的轮次、以及**由别的通道发起的轮次**都不推，那些各有回复渠道。
- **过程可选转发**：「展示思考过程」与「展示工具调用」默认都关。工具只转发名字，参数与结果可能载有隐私。
- **后台通知可选推送**：「推送后台通知」（默认关）把记忆提炼这类后台工作留在会话里的说明原文推给绑定用户，与 Web 界面看到的一字不差，推送本身不写入会话。只推插件后台工作产生的：带可见域标签的（归属拿不准，宁可少推也不把一面人格的动静泄漏到另一面）、前台轮次的旁注（如失败转译留下的报错原文——前门为沉浸感藏起的东西不从边路漏出去）、IM 通道自己发的操作者旁注，都不推。
- **合并连发消息**：真人常把一句话拆成三条发。「合并连发消息」（默认 3 秒）把同一个人在窗口内连发的普通消息合成一轮再回复，每来一条重新计时，总等待不超过三倍窗口；正在回复时到达的几条，出队时同样合成一轮。命令（`/new` 等）不参与、立即处理，窗口里已攒的先成一轮。设为 0 关闭，恢复逐条回复。
- **像人一样发消息**：「像人一样发消息」（默认关）做三件事：回复按段落与句子拆成几条（每条约 120 字、最多 6 条，代码块与表格整段不拆）、两条之间按上一条的字数模拟打字间隔（0.4–2.5 秒，期间亮「正在输入」）、并在这条通道发起的轮次里提示模型用聊天的口吻说话（短句、口语、不用标题列表加粗）。后台轮次推过来的话同样分条。命令回执、错误提示、确认请求与过程通知不分条、不延迟；Web UI 与 CLI 不受影响。关着时行为与从前完全一致。
- **可以按人格分流**：开启 `dual_persona` 的分通道后，回复发往当前人格所属的那条通道，与你从哪条通道说话无关（见[双重人格](roleplay.md)）。

各自的协议层：

| | 通道 | 凭证 | 要注意的 |
|---|---|---|---|
| `qq_bot` | QQ 官方开放平台，WebSocket 事件网关 | AppID / AppSecret | 被动回复带 msg_id（同一条消息 60 分钟内最多回 4 条，超限降级为主动消息）；C2C 私聊 |
| `wechat_bot` | 微信官方 ClawBot 插件（iLink），HTTP 长轮询 | 设置页齿轮里**扫码绑定**——凭证不是可粘贴的 Key，而是扫码确认后由服务端下发 | 回消息必须带上入站消息的 context_token，因此按用户持久化最近一次的票据；对方从没说过话时推不出去 |
| `feishu_bot` | 飞书（中国版），官方 SDK 长连接收事件，不需要公网地址 | App ID / App Secret | 需在开发者后台开通 `im:message` 权限、事件订阅选「长连接」并订阅收消息事件；仅单聊 |
| `lark_bot` | Lark（国际版），同上 | 同上，但**与飞书不通用** | 与飞书是同一套实现的两次实例化。分成两个插件是因为国际版应用不能用于中国版，凭证与 open_id 都是两套，一个插件只能存一份凭证就只能连一边 |
| `telegram_bot` | Bot API，HTTP 长轮询 | Bot Token | 大陆直连不通，配 `proxy`（http / socks5）；启动时若报 409 说明该 Bot 已设 webhook，需先自行 `deleteWebhook` |

| 配置项 | 默认 | 说明 |
|---|---|---|
| `app_id` / `app_secret` | 空 | `qq_bot` 与飞书 / Lark。密钥存在插件状态文件里（0600），不入库 |
| `bot_token` | 空 | 仅 `telegram_bot` |
| `proxy` | 空 | 仅 `telegram_bot`，形如 `http://…` 或 `socks5://…`，留空直连 |
| `whitelist` | 空 | 允许的用户 id，一行一个（QQ 用 openid，微信形如 `xxx@im.wechat`，飞书 / Lark 用 open_id，Telegram 用 chat_id） |
| `api_base` | 官方地址 | 一般不需要改 |
| `confirm_timeout_sec` | 300 | 等待 `/apply` / `/deny` 的上限，超时按拒绝 |
| `format` | 见右 | QQ / 微信 / Telegram 是 `markdown`（平台拒绝时自动退回纯文本）与 `纯文本`；飞书 / Lark 是 `卡片`（`lark_md`）与 `纯文本` |
| `show_thinking` / `show_tools` | 关 / 关 | 是否把思考过程与工具名转发到远端 |
| `push_notices` | 关 | 是否把后台工作的说明（如记忆提炼的记录）推送到远端 |
| `merge_window_sec` | 3 | 合并连发消息的窗口（秒），0 关闭 |
| `human_pace` | 关 | 像人一样发消息：回复分条、带打字间隔，并提示模型用聊天口吻 |
