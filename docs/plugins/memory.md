## 长期记忆（memory 插件）

会话历史不是可靠的记忆：超出上下文预算时最旧的轮次会被裁掉，实测占用达 90% 时整段历史会被**物理替换**成一条摘要。`memory` 插件在会话文件之外维护一层持久事实库。

- **存储**：一条记忆一个文件，YAML frontmatter（标题 / 摘要 / 分类 / 时间）+ Markdown 正文，可直接用编辑器增删改；手工放进去的普通 Markdown 也能被索引到。位置由 `scope` 决定：`global`（默认）存 `<配置目录>/plugins/memory/memories/`，`project` 存 `<工作目录>/.wen/memories/`。启用可见域隔离（见[双重人格](roleplay.md)）后，带标签的库落在同级目录 `memories-<标签>/`。
- **索引**：每条用户消息注入一次，形如 `- 2026-05-10 约定/接口命名规范 — REST 路径用小写连字符`。索引**不落盘**，由各文件头部实时生成，因此不会与正文脱节。
- **想起来的事**（默认开）：索引只是目录，而模型实测很少主动去翻——没有明确的文本信号就不调工具。活人是聊到这件事自然想起来，不是先查目录。于是每轮拿你这句话对可读的记忆做一次**词面匹配**（中文按相邻两字、英文按单词，去掉虚词；对上标题或摘要算 3 分、对上正文算 1 分，长条目按对数压一压），把最相关的两条**正文**放进 `[想起来的事]`，排在索引之前、注明标题与更新日期。零模型调用、零依赖。太短的话（「嗯」「好的」）不触发；心跳这类机器注入的提示词不触发；不可读域的记忆不会被想起；被想起的条目在索引里照样列着。想起来就算用到，开了淡忘时会刷新它的最后使用时间。
- **工具**：`save_memory`（分类限 `偏好`/`约定`/`事实`/`踩坑`/`经历`/`边界`——前四类都是关于对方的，`经历` 是角色**自己**做过、遇到过的事（和谁去了哪、自己的生活里发生了什么、独处时做的事），心跳里过的日子由此沉淀成它自己的回忆，`边界` 见下一条；默认拒绝覆盖同名条目，需显式 `mode: replace`，覆盖前留 `.bak`）、`recall_memory`、`list_memories`（可按关键词或分类过滤）、`delete_memory`。
- **边界不失忆**：角色能说「不想」，但前后一致的前提是记得——压缩会把「上次明确拒绝过」这种事磨平，换个会话更是一无所知。`边界` 是为此设的一类：任何一方明确表达过的不愿意与坚持，正文要写清是谁、对什么、因为什么。两道分界写在判据里：「说出口的才算，委婉带开话头的不算」拦住滥存，「自己表达的边界归这一类、不归 `经历`」拦住它被当成生活片段淡忘掉——自动提炼路径**强制**这一类不淡忘（工具路径不硬拦，人为存一条会淡忘的边界是合法操作，硬拦会把工具变成猜不透的黑盒）。立场松动时走矛盾修订的老路：同一标题改写，正文交代旧立场与改变的来由，「改变要有来由」于是有了存储层的落点而不只是一句表演要求。三层保住：角色当场存、定期提炼补、压缩前提炼兜底。
- **自动提炼**：两条路径。一是**对话进行中**每隔若干轮真人对话（默认 10）用一次独立的模型调用提炼一次——大部分对话走不到压缩就结束了，只靠压缩那一次会白丢很多结论；二是**历史被摘要替换之前**再提炼一次，那次拿得到含工具调用的完整历史，也兜住进程重启丢掉的窗口。做成真正的提取而不是提示模型稍后自己保存，是因为自动压缩无人值守、历史随即被删，「稍后」可能永远不会到来。两条都可单独关掉，原始历史的保全由 `session_search` 的归档负责。
- **按日时间线**（默认开）：长期记忆是按主题的（偏好 / 约定 / 事实 / 踩坑 / 经历 / 边界），回答不了「我们最近经历了什么」——隔了几天再开口，模型只能靠检索碰运气。时间线补上这条轴：每天的对话攒进当日缓冲（不新增模型调用），新一天的第一轮对话触发一次收束，把昨天提炼成一行「日期 | 关键事件」，最近几条随对话注入。没有实质内容的一天不硬凑一行，否则很快会被「聊了聊天」填满。按可见域分文件：对话属于哪条故事线，它的时间线也属于那条。
- **矛盾修订**：提炼时会拿到已有记忆的标题**与摘要**，新结论推翻旧记忆时就地修订那一条（覆盖前留 `.bak`），并要求在正文里交代被推翻的旧说法与大致时间。给清单只看标题认不出「饮食禁忌」与「喜欢香菜」说的是同一件事，于是两条互相打架的记忆会一起留在库里——那比漏记一条更糟。
- **逐步遗忘**（默认关）：保存时可逐条标记一条记忆会不会随时间失去意义，只有标记过的才会淡忘。久未提及先把正文塌缩成那句摘要（细节没了、要点还在，也更像真实的遗忘），更久之后移出记忆库——移进库内的 `forgotten/` 子目录而不是删除，因为自动遗忘是这里唯一不可逆、且误删完全无从察觉的动作。两个时限都从**最后一次被用到**起算（读取命中、被修订、或在对话中被提到），常被提起的记忆因此永远走不到淡忘。塌缩不调模型。
- **界面上看得见**：对话进行中的提炼跑在轮次收尾之后，那时这一轮的事件流已经关闭，结果本来只能进日志。因此提炼完会在会话里留一行「🧠 记忆提炼：新增「事实/构建命令」，修订「偏好/饮食禁忌」」——实时出现、可事后回看，而**模型永远看不到它**。修订尤其需要说出来：它会覆盖已有记忆，虽然留了 `.bak`，但没人会想到去翻。

**索引开销**：索引在一次工具循环的**每一轮**都会完整发送（系统消息永不被上下文裁剪），因此有硬上限。实测一条约 31 token，100 条约 3100 token。超出字节上限时先省略各条摘要只留标题，仍超出才按最近更新截断并注明剩余条数——优先保住标题，模型才知道这条记忆存在、还能按名读取。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `scope` | `global` | 记忆库范围：全局单库 / 按工作目录分库。切换后原位置的记忆不会自动迁移；用 `project` 时建议把 `.wen/` 加进该项目的 `.gitignore` |
| `max_index_entries` | 200 | 索引最多列出的条数 |
| `max_index_bytes` | 16384 | 索引字节上限（约 170 条带摘要） |
| `max_entry_bytes` | 8192 | 读取单条记忆的返回上限 |
| `recall_max` | 2 | 每轮自动想起的条数上限，0 关闭 |
| `recall_entry_runes` | 400 | 每条想起的正文字数，超出截断、后文仍可按标题读全文 |
| `recall_max_bytes` | 2048 | 一轮想起的内容合计字节上限，装不下的条目先让；这段每轮重发且不走缓存，别开太大 |
| `recall_min_score` | 4 | 最低相关度：标题或摘要对上一个词算 3 分、正文对上一个词算 1 分；标题摘要一个词都没对上时正文要对上 4 个词。调低更容易想起、也更容易想歪 |
| `auto_extract` | 开 | 压缩前自动提炼（每次压缩多一次模型调用） |
| `turn_extract` | 开 | 对话中定期提炼（每个提炼窗口多一次模型调用） |
| `turn_extract_every` | 10 | 每多少轮真人对话提炼一次，下限 5；机器自发的轮次（心跳、定时任务）不计入。距上次对话超过半小时再开口时，会先把攒着的部分提炼掉 |
| `max_extract` | 5 | 单次最多提炼条数 |
| `timeline` | 开 | 按日时间线（每个有对话的自然日多一次模型调用） |
| `timeline_days` | 7 | 随对话注入最近多少条时间线记录 |
| `decay` | 关 | 记忆逐步淡忘（只作用于被标记过的记忆） |
| `decay_blur_days` | 30 | 多少天未提及后正文塌缩成一句要点 |
| `decay_forget_days` | 90 | 多少天未提及后移出记忆库，须大于上一项 |

## 历史检索（session_search 插件）

`memory` 存的是提炼过的结论；要回查当时的原话则用本插件。两者互补：记忆信噪比高、常驻提示词，原始对话保真但噪音大、按需检索。

- **工具**：`search_sessions`（关键词 + 日期范围，一次覆盖现存会话与压缩归档）、`read_session`（读某个会话，可按关键词或日期收窄）、`read_archive`（读某份归档全文；不传文件名则列出全部）。
- **压缩归档**：历史被摘要替换**之前**，完整原文（含思考过程与工具调用）原样写入 `<配置目录>/plugins/session_search/archives/`，并在摘要末尾留一行归档位置。只做文件写入，不发起模型调用。**被压缩过的会话在现存文件里只剩一条摘要，归档是其原文唯一的去处**，因此检索必须覆盖它，否则最值得回查的部分正好成了盲区。
- **日期筛选的坑**：会话 id 与 `Meta.CreatedAt` 是**创建**时间，而会话会跨天继续使用，所以不能只看文件名判断日期——实际按每条消息的 `ts` 过滤。两个方向的剪枝是安全的：文件修改时间早于起始日的可跳过（追加消息会更新文件时间），创建时间晚于结束日的可跳过（消息不会早于会话创建）。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_scan_sessions` | 300 | 单次最多读取的会话数，按时间从新到旧；超出会在结果里注明 |
| `max_snippets` | 3 | 每个会话最多返回的摘录数 |
| `max_bytes` | 8192 | 单次返回上限 |
| `max_archives` | 20 | 保留的压缩归档数，0 = 不归档；按可见域各留这么多份 |

## 技能手册（skills 插件）

外面那套「技能」——一批用户自己安装的 SKILL.md，模型按需读取——在这里就是一个普通插件，核心不为它加任何东西。默认不启用（目录是空的，开着只多两个用不上的工具）。关掉角色演绎那组插件时，这是让它去干具体活儿的入口。

- **目录结构**：技能目录下每个子目录一个技能，里面放一份 `SKILL.md`，头部用 YAML frontmatter 写 `name`（可省，默认取目录名）与 `description`（必填，缺了这条不加载——没有用途说明，模型无从判断什么时候该读它）。目录名限小写字母、数字、连字符与下划线。
- **常驻的只有清单**：系统提示词里放的是「名称 + 用途」一行一条，正文一个字都不放。超出条数上限的不会消失，模型用 `list_skills` 看得到完整清单。
- **正文走工具返回值**，这是刻意的：按需加载意味着内容会在第 N 轮才出现，塞进系统提示词或每轮状态块都会让整段前缀作废、提示词缓存全部落空；而工具结果是追加进历史的，此后前缀不再变动。
- **工具**：`read_skill`（读某个技能的正文，超上限截断）、`list_skills`。
- **改完目录点一下扫描**：设置页齿轮里有「重新扫描技能目录」，会报出解析到几个、哪些没加载成功以及原因，说明文字里也带着当前生效的完整目录路径——不然「我的技能怎么没出现」只能靠猜。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `dir` | 空 | 技能目录，留空用 `<配置目录>/plugins/skills/` |
| `max_list` | 30 | 常驻清单最多列出的条数 |
| `max_bytes` | 32768 | 读取单个技能正文的返回上限 |
